# 06 은퇴 현금흐름 시뮬레이터

작성일: 2026-11-07. 기존 디자인·7개 메뉴·부모 메모리 입력 유지 구조를 보존한다. 새 법정 연금·수당 산식이나 세후 변환, 일반 금융자산·부채·저장소·AI API는 추가하지 않는다.

## 입력 연결과 누락 처리

`05`의 명퇴/정년별 퇴직일, 연금제도, 공식 월연금·개시일·퇴직수당·명퇴수당 및 세전/세후 구분을 `calculateRetirementScenario`로 검증한다. 조회 시 가정한 퇴직일이 바뀌면 원래 금액을 새 퇴직일로 옮기지 않는다. 공식 조회값은 사용자 직접 입력이며 기관 진위 확인이 아니다. 자격과 선정도 별도 사용자 기록이다.

`03`의 공제회 퇴직 적립금/공식 일시금과 `04`의 IRP·연금저축 잔액·수익률·수수료·인출 조건은 재사용한다. 퇴직까지의 납입은 `05`의 종료일·수익률 조건을 따른다. 계좌를 `04`에서 제외하면 인출도 생성하지 않는다. 원본 입력은 변경하지 않는다. 퇴직 후 추가 납입·급여·저축은 생성하지 않는다.

필수 월연금, 포함한 퇴직수당·공제회·계좌 잔액이 없거나 날짜·금액 기준이 맞지 않으면 계산 불가다. 0원은 직접 입력했거나 실제 계산상 발생한 경우만 사용한다. 퇴직수당과 공제회를 사용자가 분석에서 명시적으로 제외할 수 있지만, 결과에 제외 원천과 부분 결과임을 표시한다. 미입력이 곧 0원이라는 뜻이 아니다.

명퇴수당은 자격·선정·공식 금액이 모두 확인되어야 지급 이벤트를 만든다. 미확정/누락이면 원장 `honorary=null`, 결과 `partial=true`로 남긴다. 합계·연도별 표는 확인된 금액과 미확정 항목을 구분한다. 사용자가 미선정으로 기록한 경우와 정년 시나리오는 명퇴수당 유입 대상이 아니다.

기존 적립 모듈은 부분 월을 제외한다. `05`에서 기준일·최종 계산일 차이로 합산을 보류한 경우, 사용자가 **최종 계산월부터 퇴직일까지 추가 납입·수익 없음**을 확인해야 `06`에서 해당 값을 퇴직 시점 기초 잔액으로 연결한다. 기본은 미동의/차단이다. 이 가정을 실제 계약상 일할 계산의 검증으로 표현하지 않는다.

## 월별 원장과 중복 방지

최종 연령 기본값은 90세다. 1~120세, 퇴직 후 100년까지 지원하며 해당 나이에 도달한 달 말일까지 분석한다. 윤일 생일의 연령 표시는 일반 달력 기념일 말일 보정이며 법정 정년 도달일 판단과 다르다. 원 단위 안전 정수 범위를 초과하면 숫자를 표시하지 않는다.

1. 기초 자산에는 공제회·IRP·연금저축의 퇴직 시점 잔액만 넣는다. 별도 일반 금융자산 입력은 없고 지급 현금 원장은 0에서 시작한다. 미래 퇴직수당·명퇴수당을 미리 더하지 않는다.
2. 공적연금은 공식 지급개시일이 속한 달부터 월액 전액을 유입하는 가정이다. 개시 전 월에는 확정된 지급 일정상 유입이 없다. 월 중 개시의 법정 첫 지급액·일할 계산은 새로 산정하지 않는다. 월액 자체가 없으면 전체 계산을 보류한다.
3. 선택한 연 조정률은 개시 월로부터 12개월 뒤부터 매 12개월 적용한다. 미선택은 조정 없음이다. 고정 사용자 가정이며 법정 연금 인상률·물가 연동·지급정지·감액을 재현하지 않는다.
4. 퇴직수당·명퇴수당은 지정 지급일이 속한 달에 한 번만 외부 유입한다. 미입력 지급일의 기본은 해당 퇴직일이라는 명시적 가정이다. 실제 지급일을 조회하지 않는다. 퇴직 전 지급일은 오류, 분석 종료 뒤 지급은 기간 내 미유입이다.
5. 공제회 일시금은 기존 잔액을 현금으로 옮긴다. 수령 전 대기 잔액은 0% 보유 가정이며 일시 수령 때 자산이 새로 증가하지 않는다. 가상 분할은 기존 `simulateVirtualWithdrawals`를 재사용한다. 개시 전 대기에도 선택 가정 이율로 월 기념일 운용하고, 첫 인출은 개시일 한 달 뒤다. 기간은 기존 모듈의 5/10/15/20/25/30년, 마지막 회차 잔액 정산이다. 공식 상품의 수령 자격·지급 방식이 검증됐다는 뜻이 아니다. 일시금과 분할은 동시에 생성하지 않는다.
6. IRP·연금저축은 기존 `simulateWithdrawal`과 `growMonth`를 재사용한다. 퇴직 후 수령 개시까지 월 기념일 운용 → 첫 인출은 개시 한 달 뒤 → 균등 기간 인출 또는 희망 정액 인출. 개시일은 해당 퇴직일 이후여야 하며 시나리오별 수정할 수 있다. 기간 종료 시 정액 방식의 잔여자산은 이후 동일 수익률·수수료로 운용하되 추가 인출은 없다. 균등 방식은 마지막 회차에 잔액을 정산한다.
7. 계좌 이벤트는 `기말잔액 + 지급액 - 직전잔액`만 투자손익으로 인정한다. 지급액은 계좌 감소와 현금 증가에 동시에 반영하여 전체 자산에서 상쇄한다. 퇴직급여 IRP 이전은 계속 비활성화하며 이전 검토액을 다시 더하지 않는다. 일반 계좌 환급 재투자 자산·환급 현금은 별도로 만들지 않으며, 사용자 계좌 잔액에 이미 포함된 자금은 한 번만 사용한다.
8. 수입·예정 인출을 반영한 뒤 생활비·특별 지출을 현금으로 충당한다. 예정 인출 외에 계좌를 강제 매각하거나 임의 인출하지 않는다. 현금은 별도 수익률 없이 보유한다.

원장 검증식은 매월 다음과 같다.

`기말 전체 금융자산 = 기초 전체 금융자산 + 공적연금 + 외부 일시 수당 + 투자손익 - 실제 충당 지출`

공제회 수령·IRP·연금저축 인출은 이 식의 외부 수입에 넣지 않는다. 현금 유입 표에서는 내부 이동으로 따로 표시한다. BigInt 항등식 검사와 원 단위 안전 범위 검사를 수행한다. 계좌별 수익·수수료는 기존 모듈의 월 환산·반올림 기준을 유지한다.

## 생활비·물가와 부족액

공통 생활비 적용이 기본이다. 가격 기준일을 비워 두면 두 퇴직일 중 빠른 날을 공통 가격 기준으로 쓰고, 정년 첫해는 경과 물가를 반영한다. 따라서 같은 미래 달에는 같은 생활비 경로를 적용한다. 별도 생활비 선택 시 각 퇴직일이 기본 가격 기준이며 시나리오별 첫해 금액을 입력한다. 명시적인 가격 기준일도 지정할 수 있다.

연 물가상승률은 필수 입력(0%도 직접 입력)이다. 기준월에서 12개월 단위로 `월 생활비 × (1+연율)^경과연수`를 원 단위 반올림한다. 미래 가격 기준일을 입력하면 과거 월에는 해당 기준으로 역산한 가정 금액이다. 생활비 변경일을 지정하면 해당 월의 새 금액을 기준으로 다시 물가를 반영한다. 물가상승률·공적연금 가정 조정률은 -20~30%의 입력 범위이며 경제 전망을 보장하지 않는다.

퇴직일이 1일이면 그 달부터, 그 외에는 다음 달부터 월 생활비를 반영하여 퇴직 전 기간의 생활비를 임의 생성하지 않는다. 월 중 부분 생활비는 일할 계산하지 않는다. 특별 지출은 날짜·금액·적용 시나리오를 기록하며 퇴직 전 또는 분석 종료 후 지출은 해당 은퇴 이후 원장에서 제외했다고 알린다.

현금이 부족하면 실제 충당 지출은 가용 현금까지만 인정하고 부족액·최초 부족월·누적 미충당 지출을 표시한다. 계좌 잔액이 남아 있어도 현금이 부족할 수 있다. 미충당 지출은 소비하지 못한 요구액이고 부채가 아니며, 이후 현금에서 자동 상환하거나 총자산에서 부채처럼 차감하지 않는다. 생활비를 온전히 충당하지 못해 잔액이 커 보일 수 있으므로 같은 연령 표에도 누적 부족액을 함께 표시한다. 월 안에서 지출일과 입금일이 어긋나는 일별 유동성 문제는 분석하지 않는다.

## 세금과 비교의 한계

세전 조회액 경로는 **세금 미반영 시뮬레이션**이다. 세전 수입과 실제 지출을 비교하면 지출 가능액을 과대평가할 수 있다. 입력 세후 경로도 미래 투자소득세를 계산한 실제 실수령액이라고 표현하지 않는다. 선택한 기준과 다른 원천을 자동 환산·혼합하지 않는다. IRP·연금저축 자체 추정 잔액은 세전이므로 세후 경로에서 사용할 수 없다. 이는 세금 모듈이 검증되지 않은 한계다.

공적연금·사적연금·공제회의 과세방식·수령 자격은 다르다. 이번에는 새 세법 공식을 구현하지 않았다. 기존 근거는 `pension-calculation-research.md`, `ktcu-calculation-research.md`, `irp-pension-research.md`를 참조한다. 연금 지급정지·감액·연금수령한도·퇴직소득 과세이연·공제 원금과 운용수익 원천별 과세는 미반영이다.

60·65·70·75·80세 및 사용자 지정 연령에 도달하는 동일한 달 말일의 잔액을 조건부로 표시한다. 아직 퇴직 전이거나 분석 종료 뒤인 시나리오는 null/비교 불가이며 0원 경로를 생성하지 않는다. 두 시나리오 모두 퇴직한 이후에도 퇴직 전 근로소득·저축·생활비가 없으므로 **동일 연령의 완전한 비교 불가**를 유지하고 우열·차액·승자를 생성하지 않는다. 비교 표에는 누적 미충당 지출도 함께 표시한다.

## 파일 구조와 검증

- `cashflow-input.ts`: 부모 메모리에 유지하는 공통/시나리오 입력 계약과 빈 금액.
- `cashflow-validation.ts`: 월말·연령·날짜·생활비·가정 입력 검증.
- `cashflow-engine.ts`: 자산 내부 이동, 월별 지출·부족액, 연도/연령 집계 순수 원장.
- `cashflow.ts`: 기존 05·03·04 엔진 연결, 지급 스케줄·세전/세후 검증·동일 연령 비교.
- `cashflow-panel.tsx`: 생활비·지급 조건, 잔액 그래프, 월별 원장·집계 및 제한 안내.

합성 입력의 단위 테스트는 개시월, 일시 지급 시점, 선정 미확정, 내부 이동·자산 항등식, 계좌 고갈, 생활비·물가·변경·특별 지출, 원 단위 안전 범위, 미입력, 세전/세후 차단, 같은 연령의 퇴직 전 기간 미생성, 원본 불변성을 검증한다. 수학 원장 테스트 통과는 공식 지급액·세금·분할상품 검증 완료를 뜻하지 않는다.

검사 기록(2026-11-07): 단위 테스트 117/117(신규 현금흐름 18개), 전체 데스크톱·모바일 브라우저 40/40, 타입 검사·프로덕션 빌드 통과. 브라우저는 기존 원천 연결, 월별·연도별·연령별 집계, 미확정 명퇴수당, 인출 조건·특별 지출 수정, 세전/세후 차단, 입력 유지 및 320~1440px 가로 넘침을 검사했다. 최초 회귀 실행의 기존 IRP 테스트에서 초기 HTML의 날짜 입력이 클라이언트 활성화보다 앞서는 문제가 재현되어, 입력 전 메뉴 상호작용으로 준비 상태를 확인하도록 테스트를 보완한 후 전체 재검사했다. 금융 계산이나 입력 저장 코드를 바꾸어 실패를 숨기지 않았다.

다음 우선순위는 비식별 공식 지급/인출 원장과의 대조, 지급일·일할 처리 확인, 원천별 세금 및 퇴직 전 근로소득·저축·생활비의 명시적 계약 설계다. 이번 단계에서 자동으로 진행하지 않는다.
