# 교사 은퇴 플래너 최종 출시 감사 — 간편 계산 버전

후속 UI 개선(설정v8): [간편 계산·UI 개선 기록](simple-ui-final-improvement.md). 금액 표시는 정수 만원 반올림으로 바뀌었고 별도 퇴직수당 참고 시나리오가 추가됐다. 후속 회차에서는13.2% 가정 재투자 자동화,03 연도별 내역 제거,05 대시보드 정리,06 생활비 이동을 구현했다. 후속 최종 타입 검사·단위297개·브라우저114개·프로덕션 빌드가 통과했다. 최신 검증 결과·수정 파일·한계는 연결된 개선 기록의 후속 완료 보고를 기준으로 한다. 아래 v6의 금액 옵션·테스트 수치는 당시 감사 기록이며 현재 표시 계약과는 구분한다.

감사 기준일: **2026-11-08, Asia/Seoul**. 대상: 기존 Next.js 16.4.5 프로젝트, 01~06 메뉴, 설정 `simple-2026-11-v6`. 작업 시작 기준 커밋 `a3d3820`의 1~7단계를 확인하고 8단계 연결·요청문·회귀 검증을 수행한다. 이번 작업은 커밋·Push·Vercel 배포·Production 설정 변경을 하지 않는다.

**판정 범위:** 지원 조건 안의 간편 계산·요청문을 제공하는 기술적 출시 후보이다. 법령 구조·코드 산술·화면 동작의 검증과 실제 기관의 개인별 지급 예상액 검증은 다르다. 개인별 지급액·세후액을 확정하는 금융 서비스로 검증 완료한 것은 아니다.

## 1. 전체 구현 기능과 공통 데이터 흐름

실제 코드를 확인한 기능:

- 교사 기본정보, 세 연금제도 선택, 승급월을 반영한 예상 퇴직 호봉, 정년 후보·선택 명퇴일.
- 공제회 장기저축급여 적립·일시금/가상 분할, IRP·연금저축 월납/연납 적립, 조건부 세액공제 재투자.
- 지원 범위 내 명퇴수당·퇴직수당 자동 추정, 별도 제도별 공적연금 조건부 추정과 선택적 조회값 우선 경로.
- 계좌별 선택 가입일·55세/5년·확인된 이연퇴직소득 예외·신청·수령한도·재원별 과세 안내.
- 소득 공백·자산 용도·공제회 지급 전후·생활비 부분 비교·규칙 기반 조언 5개.
- 기본정보만으로 생성 가능한 익명 AI 요청문, 미리보기·편집·복사·최신성 확인·개인정보 형태 점검.

`SimplePlanner`의 공통 입력 → `calculateSimple`의 퇴직일·호봉·수당·공적연금·적립금·수령조건 → `calculateRetirementAnalysis` → `generateRetirementAdvice`를 05와 06에서 함께 사용한다. 06은 같은 계산 모듈을 호출하며 수익률·수당·연금·복리 산식을 복제하지 않는다. 계산 결과와 입력 상태를 정리하는 `prompt-context.ts`만 추가했다.

이번 변경에서 기존 금융 계산 모듈은 변경하지 않았다. 납입·복리·수당·공적연금·수령 조건과 수익률 가정은 그대로다. 요청문의 수익률 표기도 공통 설정값을 참조하도록 연결했다.

## 3. AI 요청문 최종 개선

분석 유형을 다음 여섯 이름으로 정리했다.

1. 은퇴설계 종합 분석
2. 명예퇴직·정년퇴직 관련 조언
3. 공적연금 및 퇴직급여 분석
4. 교직원공제회 수령 전략
5. IRP·연금저축 활용 전략
6. 직접 질문 작성

요청문 앞부분에 **입력 상태와 결과 상태를 별도 표시**한다. 사용자 입력값은 기초자료 입력 여부이며 사용자가 최종 산출액을 직접 입력했다는 뜻이 아니다. 공식 조회값/법령 기반 추정값/가정 기반 시뮬레이션/사용자 추정 입력과 계산 불가를 구분한다. 미입력·불완전 입력·명시적0원은 분리하고 모든 조건부 결과에 추가 검증 필요를 유지한다. 잘못되거나 오래된 공식 조회 입력은 계산 불가이며 자동 추정으로 몰래 대체하지 않는다.

현재 잔액과 활성 월납/연납 입력은 요청문 간단·상세 분량 모두 포함한다. 화면에서 연납으로 바꿨을 때 보존된 과거 월납 값은 내보내지 않는다. 소득을 추가 입력했다면 적용하는 소득·해당 구간 자료·계산 가능한 적용비율을 함께 안내한다. 법정 산식 본문은 기존 엔진의 출력만 사용한다.

기본정보만 있을 때는 현재 경력 단계의 준비 방향·명퇴/정년 고려사항·개시 조건·추가 소득자료와 공식 조회 우선순위를 명시한다. 다른 메뉴의 금액을 생성 조건으로 요구하지 않는다. 기본정보만으로 기존 명퇴수당 등 계산 가능한 결과가 있으면 조건부 결과로 포함하되, 연금·공제회·IRP·연금저축 누락액을 만들지 않는다.

모든 입력이 있을 때는 기존 1~7단계 결과·계산 방법·신뢰도·수령조건·소득 공백·생활비·규칙 조언을 연결한다. 추가로 강점/위험, 명퇴·정년, 공백, 공제회, 계좌 인출, 세금/한도, 목돈/분할, 계산 가능한 생활비 차이, 공식 자료, 실천 방안의 10개 분석 항목을 요청한다. 없는 반대 시나리오·소득·세금을 만들거나 수익률·지급액을 보장하지 말라는 조건을 넣었다.

## 5. 공식 계산과 추정·금액 대조 기록

공식 자료의 산식 확인, 사용자 공식 조회 입력, 앱 조건부 계산, 기관 실제 개인 지급액 대조를 구분했다.

- 국민연금은 기존 `public-pension.test.mjs`에서 2026년 공단 예상월액표의 B=300만원·전 기간2026년 이후 10/20/30/40년 사례(332,900/665,800/998,700/1,331,600원), B=41만원·25년 상한 사례와 대조한 기록이 있다. 대표 고정소득 표 사례의 산술 대조일 뿐 개인 연금 검증이 아니다.
- 공무원/사학 개인별 월연금·명퇴수당·퇴직수당·공제회 실제 지급 예상액 전체를 공단/기관 조회로 대조한 기록은 없다. 해당 항목을 실제 금액 검증 완료라고 표현하지 않는다.
- 공식 조회액은 사용자 직접 입력 출처다. 앱이 기관에 접속하거나 진위를 확인한 결과가 아니다. 현재 퇴직일과 맞는 입력인지 등 형식·연결 검증만 한다.
- 법정 구조를 구현한 경우에도 소득·기간·재분배·계수·상한 경과자료가 없으면 금액을 내지 않는다. 고정소득·고정수익률은 가정 시뮬레이션으로 남긴다.

8단계에서도 [국세청 과세 안내](https://nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7888&mi=6608)와 [공제회 공식 분할 안내](https://www.ktcu.or.kr/PPW-FIA-300100)를 재확인했다. 공제회 5%는 2026-07-01 기준 변동급여율이며 앱에서는 고정 가정이다. 5/10/15/20/25/30년과 첫 지급 조건·세후 전환 제한을 유지한다. 새 법정 수치를 도입하지 않았다.

## 6. 남아 있는 금융 계산 위험

1. 일반 초·중등 호봉제·연속 재직/납부 가정이다. 시간제·휴직·합산·기수령·구법·기관별 정관 등 미지원은 별도 확인해야 한다.
2. 직역연금의 평균소득·소득재분배·적용비율, 국민연금의 실제 납부기간·재평가 B값·크레딧은 개인별 자료가 필요하다. 미래 가격·법 개정을 예측하지 않는다.
3. 세전 금융 적립금·2026년 가격 고정 수당·일부 세후 조회값은 같은 실제 현금 기준이 아니다. 화면과 요청문이 기준을 안내하며 세금 기준 혼합 월액은 합산하지 않는다.
4. 공제회 가상 분할은 전체 세전 원금을 사용한다. 실제 전환 세후액·최소단위·대여 상계·휴일·끝수 검증이 남는다.
5. IRP/저축 인출 일정·세후액·타 연금·근로/임대소득·생활비 전체 현금흐름·건강보험료·물가·장수 위험을 완전히 계산하지 않는다. 적립금 전액을 즉시 현금으로 보지 않는다.
6. 세액공제 재투자는 실제 환급 보장이 아니다. 은퇴 후 개시·인출을 실행하는 경우 기존 계속 납입 시나리오와 별도의 현금흐름 설계가 필요하다.

## 9. 개인정보 보호

- 기본 익명화: 생년월일·최초 임용일 원문·학교명·이름·식별필드 제외. 연령대·임용연도와 계산 조건만 사용한다.
- 금액은 기본10만원 단위 반올림이며 사용자가 구간/정확한 금액으로 바꿀 수 있다. 익명화는 완전한 재식별 방지를 뜻하지 않는다.
- 원본 입력 객체를 통째로 출력하지 않는다. 비활성 과거 납입값·기관 자유 메모·임의 식별 속성을 내보내지 않는다.
- 질문은 검토 전 제외하고, 검토 후에도 감지된 개인정보 줄을 제거한다. 편집본은 이메일·전화·학교명·긴 식별번호·허용되지 않은 날짜·외부주소 등의 형태가 감지되면 자동 복사를 막는다. 패턴 검사는 완전한 개인정보 판별기가 아니다.
- 입력/설정이 바뀌면 이전 생성본의 자동 복사를 보류한다. 사용자가 확인·재생성한 최신 결과만 복사한다. 수동 선택·편집·외부 붙여넣기는 사용자의 행위다.
- 로그인·DB·브라우저 저장·외부 AI API·자동 송신을 추가하지 않았다. 공식 AI 사이트 링크는 기본 주소만 열며 요청문을 URL에 넣지 않는다.
- 입력·요청문은 메모리에서만 다루며 정확한 원본을 콘솔이나 파일로 기록하는 기능은 없다. 테스트 첨부·스크린샷은 가상 사용자 데이터만 포함하며 Git 제외된 `test-results/`에 둔다.

## 10. Vercel 재배포 가능 여부

로컬 프로덕션 빌드가 성공하므로 현재 소스는 **기술적으로 재배포 후보**다. 실제 Vercel 프로젝트 설정·권한·Production 실행은 이번에 변경·검증하지 않았다. 따라서 Vercel 배포 성공을 보장하거나 완료로 보고하지 않는다. 별도 사용자 지시 전 커밋·Push·재배포하지 않는다.

공개 문구는 조건부 간편 계산·미확인/미지원·기관 확인 필요를 유지해야 한다. 개인별 금액과 세무 전반의 검증이 끝난 서비스처럼 소개하면 안 된다.
