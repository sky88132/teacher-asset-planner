# 교직원공제회 상품 조사 및 가정 시뮬레이션

자료 확인일: **2026-11-07, Asia/Seoul**. 한국교직원공제회 공식 페이지를 실제 열람했다. 기존 앱에 상품별 조회 기록과 자체 적립·인출 가정을 추가했으며, 공식 상품 예상급여금 자동 산정은 활성화하지 않았다.

장기저축의 금리 결정은 정관 제43조의2·제43조의3에 따른 시중금리·운용 관련 지표와 심의 절차를 거치므로 미래 금리를 자동 예측하지 않는다. 6개월 이상 미납·퇴직 외 탈퇴는 별도 지급 기준이 있다. 앱의 '납입 종료 후에도 이자 가정'은 이런 상품 효력·탈퇴 판정과 별개다. 운용 수수료 없음 안내는 [공식 장기저축 소개](https://pick.ktcu.or.kr/lsb)에서도 확인했지만, 이를 모든 상품·세금·대여 상계에 확대 적용하지 않는다.

## 2. 공식 예상급여금 자동 계산을 비활성화한 이유

- 장기저축의 과거 정산금·이율 이력·특별가산금·날짜별 부가금 및 개인별 과세를 재현할 완전한 명세가 확보되지 않았다.
- 분할급여금의 실제 전환일·첫 지급일·회차별 변동금리·과세·끝수까지 대조할 개인별 원 단위 예제를 확보하지 않았다.
- 퇴직생활급여의 세 가지 유형은 현금흐름과 과세·중도해지 규칙이 다르다. 유형별 원 단위 공식 계산 사례 대조는 미완료다.
- 공식 페이지에서 입력 없이 보이는 0원·옛 조회일은 개인의 공식 예상액으로 취급하지 않는다. 앱에서는 금액이 없으면 결과 없음으로 둔다.

따라서 모든 공식 상품은 '미검증' 상태다. 실제 계산 가능한 부분은 아래의 **독립적인 수학 모델**이며, 상품 약관을 구현한 것으로 주장하지 않는다. 공식 확인 이율을 선택해도 결과의 출처는 자체 시뮬레이션이다.

## 3. 입력과 결과의 분리

공식 기록은 다섯 상품별로 `quotes`에 별도 저장한다. 사용 여부·금액·조회일·가정 수령/퇴직일·세전/세후·월/연/일시금 단위를 모두 확인한 경우만 표시한다. 사용자가 직접 전사한 값이며 앱이 공제회에 로그인하거나 진위를 확인하지 않는다. 사용을 해제하면 결과에서 제외하되 기록은 유지한다.

적립 가정의 입력은 현재 기준일 잔액, 잔액 출처, 현재 납입액(기록용), 향후 납입액, 납입 종료일, 퇴직일, 월 초/말 납입, 이율 출처와 변경일·변경 이율이다. 현재 잔액은 세전 기준으로 입력한다. 현재 월 납입액을 잔액에 다시 더하지 않는다. 미래 공식 예상급여금을 현재 잔액으로 사용하거나 적립 전망에 자동 합산하지 않는다.

가상 인출 시작금액은 사용자 별도 입력 또는 유효한 장기저축 자체 적립 전망으로 선택한다. 상품별 공식 조회액을 자동으로 사용하지 않는다. 퇴직생활급여·분할급여금 화면에는 장기저축 적립 모델을 적용하지 않는다. 가상 인출은 그 상품의 수령금액이 아닌 별도 자금 모델로 제공한다.

## 4. 자체 적립 모델의 수학적 정의

연 유효 가정 수익률을 `r`, 월 수익률을 `q`라 하면:

`q = (1 + r)^(1/12) − 1`

현재 잔액 `B0`에서 월 납입금 `D`를 납입한다. 월 말 납입은 `Bt = B(t−1) + round(B(t−1)×q) + D`, 월 초 납입은 `Bt = B(t−1)+D+round((B(t−1)+D)×q)`다. 납입 종료 후 `D=0`이며 퇴직 전까지 월 이자를 가정한다. 총증가액은 `최종잔액−기준잔액−향후납입합계`로 계산한다. 기준잔액에 과거 이자가 포함될 수 있으므로 그래프의 기준잔액+향후납입 선을 '전체 납입 원금'이라고 부르지 않는다.

구현은 `log1p`·`expm1`로 월 수익률을 구하고 10^-12 단위 정수로 반올림한다. 그 후 잔액과 이자는 BigInt 원 단위로 처리한다. 월 이자는 원 단위 사사오입(양수 half-up), 표시 금액은 안전 정수 범위를 검사한다. **이 반올림은 앱의 가정 규칙이며 공제회의 급여 끝수 규칙이 아니다.**

기간은 기준일의 매월 같은 일자를 기념일로 삼고 해당 일이 없으면 월 말로 제한한다. 원래 기준일에서 매번 계산해 날짜 밀림을 피한다. 퇴직일·납입 종료일까지 완성된 개월만 계산하고 부분월은 일할 계산하지 않는다. 같은 날짜·같은 계산월은 0개월일 수 있다. 첫 납입은 첫 계산월에만 반영하며 미래 납입 월수는 완성된 납입 개월수로 제한한다.

금리 변경 시 해당 변경일 이상인 첫 계산월 기념일부터 새 수익률을 한 계산월 전체에 적용한다. 월 중 변경의 일할 산정은 하지 않는다. 변경 시나리오와 변경이 없는 동일 조건의 기준 시나리오를 비교한다. 공식 이율 고정 가정은 해당 이율 시행 기준일보다 앞선 잔액 기준일에는 사용할 수 없다. 과거 전체 금리 이력 재현은 제공하지 않는다.

계산 기준일은 함수 인수이며 함수 내부에서 날짜를 정하지 않는다. 사용자 가정 수익률은 0~20%, 소수 넷째 자리, 적립 전망은 최대 720개월로 제한한다. 이는 계산기 지원 범위이며 상품 가입 한도가 아니다. 0원은 명시 입력일 때 허용하고 공란·음수·지수 표기·비정상 날짜·범위 초과 결과는 거부한다.

## 5. 가상 인출 모델

퇴직일 기준 자금 `P`, 일정한 월 가정 수익률 `q`, 수령개월 `n`에 대해 수학적 균등 인출액은 `A=P×q/[1−(1+q)^(-n)]`, 0%일 때 `A=P/n`이다. 월 지급은 원 단위로 내림한다. 매월 원 단위 가정 이자를 먼저 반영하고 월 지급을 차감한다. 마지막 달에는 남은 원리금 전부를 지급하여 원 단위 잔액을 정산한다. 실제 마지막 지급액은 일반 월 지급액과 다를 수 있다.

5/10/15/20/25/30년을 **가상 비교 기간**으로 제공한다. 이 선택지가 모든 공식 상품에서 가능한 가입기간을 뜻하지 않는다. 첫 인출일은 퇴직일에서 1개월 뒤 기념일이다. 공제회의 5/15/25일 지급일 규칙을 모방하지 않는다. 인출 모델의 가정 수익률은 적립 이율과 독립적으로 입력한다.

총수령액은 월별 지급액의 합이며, 동시에 `시작금액+월별가정이자합계`와 같아야 한다. 세금·수수료·가입조건·물가·중도해지·공제회 대여 상계는 미반영이다. 세후를 계산하거나 공제회 분할급여금으로 표현하지 않는다.

## 6. 검증과 공식 예시 비교의 한계

단위 테스트는 월 납입 0원·수익률 0%·0/1개월·월 초/말 납입·윤년·금리 변경·조기 납입 종료·퇴직 이후 인출·기간별 현금흐름 합계·마지막 잔액 0·비정상 입력 및 범위 초과를 검증한다. 합성 입력의 수학적 검증이며 상품 지급액 정확도 검증과 다르다.

공식 장기저축 비교표는 월 150만원, 10년, 5% 가정에서 원금 180·이자 52를 **백만원 단위**로 제시한다. 앱 테스트는 세전 합계 232백만원과 자체 모델의 차이가 1백만원 미만인 규모인지만 확인하며 원 단위 일치로 간주하지 않는다. 공식 예시는 매월 17일 납입·퇴직월 말 기준이고 앱은 월 기념일 모델이다. 세후 비교표나 그 차액으로 개인별 세금을 역산하지 않는다. [공식 비교표](https://www.ktcu.or.kr/PPW-FIA-101000)

브라우저 테스트는 원·만 원, 출처별 금액 분리, 상품 전환, 메뉴 이동·기본정보 보존, 그래프·월별 일정, 화면 넘침·새로고침 초기화를 검사한다. 기존 공적연금·퇴직수당·기본정보 테스트도 함께 실행한다.

실행 결과: 전체 단위 테스트 70개, 데스크톱·모바일 브라우저 테스트 24개 통과. 마지막 계산 메타데이터 변경 후 공제회 브라우저 테스트 6개를 재실행해 통과했다. `npm.cmd run typecheck`, `npm.cmd run build`도 통과했다. 이 결과는 공식 지급액 정확성 인증이 아니다.

## 7. 미확인 사항과 다음 우선순위

1. 상품별 최신 약관·상세 산정명세와 원 단위 공식 사례를 확보한다. 기존 정산금·특별가산금·일자별 이율·세금·끝수까지 별도 검증한다.
2. 장기저축 신규 일반 재직, 분할급여금, 퇴직생활급여 각 유형을 따로 검증한 범위에서만 공식 상품 계산을 활성화한다.
3. 중도해지·미납·가입자격·개인별 과세는 충분한 공식 근거와 입력을 갖춘 뒤 추가한다. 현재 금액을 세후 또는 실지급액으로 확정하지 않는다.

UI와 금융 모듈을 분리했고 입력은 화면 메모리에만 보관한다. Supabase·서버 저장·브라우저 저장소는 연결하지 않는다. 검증 비율이나 실제 지급액 일치 확률을 생성하지 않는다. 다음 단계 구현·커밋·푸시는 별도 사용자 지시를 기다린다.
