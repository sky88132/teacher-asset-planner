# 로그인 없는 간편 계산 버전 점검

점검일: 2026-11-07. 기존 7개 메뉴·디자인·React 상태·계산 엔진을 보존한다. Supabase, 인증, 클라우드 저장은 보류하며 정밀 연금 계산은 준비 중이다. 이전 Supabase 설계 문서는 향후 검토 자료다.

## 변경 사항

- 사용자 요청에 따라 가운데 입력 보관 안내 카드는 삭제하고, 왼쪽 개인정보 보호에 '입력 정보는 저장되지 않으며, 새로고침하면 초기화됩니다.' 한 문장으로 정리했다.
- 금융정보는 서버·브라우저 저장소에 저장하지 않으며 AI 요청문도 자동 전송하지 않는다. 사용자가 외부 AI에 직접 붙여넣을 때는 그 서비스로 정보가 전달됨을 안내한다.
- 상단을 '로그인 없는 간편 계산'으로 변경하고 현재 단계의 진행 표시·필요 입력 안내를 추가했다. 진행 표시는 화면 위치이지 계산 완료·공식 검증 상태가 아니다.
- 기존 색상·메뉴·카드 구성을 유지한다. 개인정보 보호 문구는 기존 왼쪽 영역의 반응형 표시 방식을 따른다.
- 실제 데이터에 연결되지 않은 미리보기 막대 그림을 실제 비교/현금흐름 결과 카드·그래프로 이동하는 버튼으로 교체했다. 별도 요약 합산은 계속 준비 중이며 임의 숫자를 표시하지 않는다.
- 기존 비교 테스트의 메뉴 선택을 navigation 영역으로 한정하여 새 결과 버튼과 구분했다. 금융 계산식과 데이터 타입은 변경하지 않았다.

## 메뉴별 점검

모든 메뉴에서 입력 유지·모바일 폭·단계 표시를 검사했다. 저장 안내는 왼쪽 개인정보 보호에만 두었다. 금융 메뉴의 누락 정보·날짜·단위·금액 표시는 기존 브라우저·단위 테스트로 확인했다.

| 메뉴 | 정상 작동 확인 | 공식 검증과 계산 제한 |
| --- | --- | --- |
| 01 교사 기본정보 | 학교/제도 선택, 날짜·경력, 필수·순서 검증, 이동 후 유지 | 특수 경력 선택만으로 공단 인정기간을 확정하지 않음 |
| 02 공적연금·퇴직수당 | 원/만원, 조회 조건·세금 구분·출처, 제도별 독립 입력, 수정 즉시 결과 반영 | 공식 조회값은 사용자 직접 입력. 연금·퇴직수당 자동 금액은 검증 전 차단. 명퇴수당은 별개 |
| 03 교직원공제회 | 잔액·납입·기간·이율 변경, 적립 그래프, 상품별 조회액, 가상 인출 | 자체 적립·가상 인출은 조건부 추정. 공식 상품 급여금·세후 산식은 미검증 |
| 04 IRP·연금저축 | 계좌별 잔액·납입·수익률·수수료, 원금/향후 투자손익, 그래프·인출·재투자 비교 | 일반 국세 공제 범위의 테스트와 실제 환급·세후액 검증은 다름. 연금계좌 내 환급 재투자·퇴직급여 IRP 이전은 차단 |
| 05 명퇴·정년 비교 | 시나리오별 날짜·조회액, 공제회/계좌 입력 재사용, 수정 즉시 반영, 모바일 세로 비교 | 공식 조회 가정 퇴직일이 맞아야 연결. 명퇴 자격/선정 구별. 자동 정년일은 확인된 국공립 일반 교사 범위에 제한 |
| 06 은퇴 현금흐름 | 월 원장·연도/연령 집계, 생활비·물가·특별 지출·지급일, 부족 시점·그래프 | 세금 미반영/입력 기준 시뮬레이션. 미확정 원천은 부분 결과로 명시. 퇴직 전 급여·저축 등이 없어 최종 유불리 단정 불가 |
| 07 AI 분석 요청문 | 실제 계산값·누락·신뢰도, 익명화·금액 표시, 편집·복사·실패 시 수동 선택, 변경 시 재생성 | 자동 AI 분석은 제공하지 않음. 자유 질문·편집본의 식별정보 자동 탐지는 완전하지 않아 직접 검토 필요 |

## 통합 계산 검증 범위

기존 엔진과 테스트에서 다음 사항을 대조했다. 이번 점검 범위에서 새로운 계산 오류는 발견하지 않았으며 금융 산식은 수정하지 않았다.

1. 월 공적연금은 개시 월부터 현금 유입이며 일시금 자산 합계에서 제외한다.
2. 퇴직수당과 명퇴수당은 독립된 금액·지급월을 가지며 미선정 명퇴수당은 null/부분 결과다.
3. 공제회 일시금과 가상 분할은 선택 방식 하나만 적용하고, 이미 보유한 적립금을 현금으로 바꾸는 이동을 추가 자산으로 세지 않는다.
4. IRP·연금저축은 초기 평가금액·향후 납입원금·가정 투자손익을 구분한다. 초기 잔액의 과거 원금/수익은 알 수 없다.
5. 환급 재투자는 같은 현금을 보유하는 기준과 비교하고 중복 공제를 적용하지 않는다. 05/06은 일반 계좌 환급 보조 시뮬레이션을 추가 자산으로 복제하지 않으며 제외 범위를 안내한다.
6. 시나리오별 조회값은 가정 퇴직일이 일치할 때만 사용한다. 서로 다른 날짜의 자산을 동일 시점 금액으로 합산하지 않는다.
7. 현금흐름의 계좌 인출은 내부 이동이다. 매월 기말 = 기초 + 외부 수입 + 투자손익 - 실제 충당 지출의 항등식을 검사한다. 미충당 지출은 별도로 기록하고 차입을 만들지 않는다.
8. AI 요청문은 현재 모듈의 결과를 사용한다. 누락·계산 불가는 0원으로 바꾸지 않고 조건부 추정을 공식 조회값으로 높이지 않는다.

## 테스트와 개인정보 전송 확인

- 타입 검사와 단위 테스트 129개를 실행했다. 금액·기간 경계, 원 단위, 누락/0, 합산·인출·신뢰도·개인정보 필터를 포함한다.
- 브라우저 테스트에 비회원 시나리오 2개를 추가하여 데스크톱·모바일 각각 검사한다. 기존 46개와 합쳐 50개다.
- 새 테스트는 가운데 보관 안내 삭제·왼쪽 개인정보 문구, 7개 메뉴 진행 표시·필요 입력 안내, 결과 화면 연결, 모든 메뉴의 입력 유지 및 새로고침 초기화를 검사한다.
- 입력 중 외부 HTTP 요청, 쓰기 요청, URL/본문의 시험 입력값 유출이 없는지 검사한다. localStorage·sessionStorage가 비어 있는지도 확인한다. 기존 AI 브라우저 테스트도 자동 외부 전송이 없음을 검사한다.
- 소스에서 fetch/XMLHttpRequest/sendBeacon/WebSocket·브라우저 저장 호출을 검색했다. 금융 입력 전송·저장 구현이 없으며 외부 주소는 공식 자료·사용자가 직접 여는 AI 링크다.
- 모바일은 Edge의 모바일 설정과 320·390·640px에서 가로 넘침을 검사하고 화면 캡처를 확인한다. 실제 휴대폰 검사를 대체하지 않는다.
- 이 검증은 앱이 실행한 시험 경로 범위다. 브라우저 확장 기능·사용자의 수동 복사/붙여넣기·외부 AI 서비스의 처리는 통제하지 않는다.
- 최종 결과: `npm run typecheck` 성공, `npm test` 129개 통과, `npm run test:browser` 50개 통과(데스크톱 25·모바일 25), `npm run build` 성공. 첫 전체 실행에서 새 결과 버튼 때문에 비교 테스트의 메뉴 선택자가 중복된 것을 수정한 뒤 전체를 다시 실행해 통과했다. 일반 모듈 유형·색상 환경 경고와 실패는 구별한다.

## 변경 파일과 다음 우선순위

이번 수정: `src/components/planner.tsx`, `src/app/globals.css`, `tests/browser/guest-session.spec.ts`, `tests/browser/retirement-comparison.spec.ts`, `README.md`, 이 문서. 기존 `next-env.d.ts` 개발 생성 경로 변경은 사용자 작업 상태로 보존한다.

다음으로는 실제 교사의 사용성 피드백과 실제 휴대폰 점검, 누락 입력에서 해당 원본 메뉴로 돌아가는 동선 개선을 우선한다. 금융 정확성 확대는 기존 조사 문서의 미확인 사항인 급여 경과규정·공식 숫자 사례·끝수 처리, 공제회 상품별 지급·세금, 실제 연금계좌 세금/이전 조건을 공식 자료로 추가 검증한 뒤 별도 진행한다. 현재 단계에서 규정을 새로 검증했다거나 미검증 계산을 활성화했다고 주장하지 않는다.

로그인·클라우드 저장은 사용자 반응 확인 후 다시 결정한다. Git 커밋·푸시는 별도 사용자 승인 전까지 진행하지 않는다.
