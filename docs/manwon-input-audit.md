# 만원 입력 통합 점검 (2026-11-08)

후속 작업에서 아래 당시 재현했던 금융 경계 오류 2건의 일괄 차단을 수정했다. 현재 처리 범위·공식 근거·남은 제한·회귀 테스트는 [금융 경계 수정 기록](financial-boundary-fixes.md)을 참조한다. 아래 테스트 수와 미해결 설명은 만원 변경 단계 당시의 기록이다.

## 범위 및 데이터 흐름

현재 공개 진입점은 `src/app/page.tsx` → `SimplePlanner` → `src/components/simple/`의 6개 메뉴다. 기존 네이비 테마, 메뉴, React 상태 유지, 계산 신뢰도 및 미검증 산식 차단을 유지했다.

| 메뉴 | 금액 입력/출력 조사 및 처리 |
| --- | --- |
| 01 교사 기본정보 | 금액 입력 없음. 2026년 호봉 봉급표 참고액은 공통 한국식 표시 함수 사용. 날짜/호봉 규칙 불변 |
| 02 교직원공제회 | 현재 잔액·월 납입액 2개를 만원 입력으로 변환. 적립금·납입원금·증가액·일시금·가상 분할 월액/총액은 만원/억원 표시 |
| 03 IRP·연금저축 | 계좌별 잔액·월 납입액 총 4개를 만원 입력으로 변환. 미래가치·원금·손익·합계는 한국식 표시 |
| 04 퇴직급여 | 퇴직수당·명예퇴직수당 조회금액을 만원으로 고정. 종전 원/만 원 선택기 제거. 조회일·세금·출처·자격/선정 판정 유지 |
| 05 은퇴설계 종합 | 공식 월연금 입력을 만원으로 고정. 카드·구성 그래프 금액·요약 표에 공통 포맷 적용. 월연금과 적립금/일시금 합산 금지 유지. 기준일/퇴직일/완료 월 설명 유지 |
| 06 AI 분석 요청문 | 직접 금액 입력 없음. 계산 엔진의 원 단위 결과를 기존 익명화·반올림 설정에 따라 원 단위로 명시. 화면 입력은 만원, 요청문 금액은 원임을 안내 |

과거 7메뉴의 `planner.tsx`, `pension-panel.tsx`, `ktcu-panel.tsx`, `irp-panel.tsx`, `retirement-comparison-panel.tsx`, `cashflow-panel.tsx`, `analysis-prompt-panel.tsx`는 현재 진입점에 연결되지 않은 보존 코드다. 해당 입력/표시 구조도 검색으로 구분했으며 비활성 화면의 단위·모델·기능은 변경하지 않았다. `src/lib/finance/` 및 `src/lib/ai/` 공통 엔진도 유지한다.

## UI 경계와 호환성

- `MoneyField`의 임시 편집 문자열만 만원이다. 계좌의 기존 `balance`, `monthly` React 상태는 계속 원 단위 문자열이다.
- `manwonToWon()`은 기존 BigInt 기반 `parseMoney()`를 재사용해 소수점 넷째 자리까지 원 정수로 정확히 변환한다. 임의 반올림 없음.
- `wonToManwon()`은 기존 `changeMoneyUnit()`을 재사용한다. 빈 값은 빈 값, 실제 0은 0으로 유지한다.
- 기존 `BenefitInput.money.unit`이 `won` 또는 `manwon`이어도 렌더링 시 원으로 정규화한 뒤 화면 만원으로 표시한다. 기존 값을 렌더링만으로 변경하지 않으며 사용자가 편집할 때 원 단위 상태를 기록한다. 10,000배 재해석이나 이중 환산 없음.
- 초기 기본값은 여전히 빈 문자열이며 저장소 마이그레이션은 없다. localStorage/sessionStorage/DB/서버 저장을 추가하지 않았다. 메뉴 이동은 상태 유지, 새로고침은 초기화된다.
- 입력은 천 단위 구분·만원 접미사·원 환산 설명·decimal 키패드를 제공한다. 소수점 4자리까지 허용하며 음수·문자·지수표기·안전 정수 범위 초과는 거부한다. 거부 시 직전 유효 금액을 유지함을 입력 근처에 안내한다.
- 결과 포맷은 만원/억원을 자동 선택하며 원 단위 결과를 손실하지 않도록 만원 소수점 최대 4자리를 보존한다. `null`/잘못된 결과는 0원으로 만들지 않는다.

| 화면 입력 | 내부 원 금액 |
| --- | ---: |
| 공제회 잔액 3,000만원 | 30,000,000원 |
| 공제회 월 납입 30만원 | 300,000원 |
| IRP 잔액 5,000만원 | 50,000,000원 |
| IRP 월 납입 50만원 | 500,000원 |
| 연금저축 잔액 2,000만원 | 20,000,000원 |
| 월연금 450만원 | 4,500,000원 |

표시 예: 30,000,000원 → 3,000만원, 150,000,000원 → 1억 5,000만원, 300,000,000원 → 3억원.

- TypeScript: 통과.
- 단위 테스트: 기존 151 + 신규 12 = 163개 통과, 실패 0개.
- 신규 단위 검증: A–F, 빈 값/0/0.5/1/9999/10000만원, 1원 정밀도, 음수/문자/초과 입력, 기존 원/만원 조회 데이터, 세 계좌 복리 전체 결과의 변경 전후 일치, AI 월연금 4,500,000원 반영, 기존 경계 문제 2건 재현.
- 브라우저: 설치된 Microsoft Edge, PC 1440×1000 및 모바일 390×844에서 28개 통과, 실패 0개. 기존 6메뉴·입력 유지·변경 후 갱신·차트·접힘·복사·익명화·외부 요청/저장 없음 확인 포함. 320/390/640 및 900/1440 폭에서 가로 넘침 검사 포함.
- 신규 브라우저 검증: 천 단위, 환산 설명, 소수 및 소수점 입력 도중, 음수/문자/초과 거부, 누락과 0 구분, 공식 조회액 단위 고정, 450만원 월연금의 AI 요청문 원 단위 정확성.

- ESLint: `npm run lint` 실행 시 Missing script. 현재 lint 스크립트·ESLint 설정이 없어 검사 미실행. 임의 설치/설정 추가하지 않음.

## 남아 있는 기존 금융 경계 문제

다음 두 건은 의도적으로 계산식을 수정하지 않고, 단위 변경 전후 동일한 차단 상태임을 회귀 테스트로 기록했다. 아래 테스트 통과는 오류 해결을 뜻하지 않는다.

1. **연금계좌 연간 한도 판정**: 퇴직까지 1개월, IRP 월 200만원(2,000,000원)을 입력하면 기존 엔진은 12개월 연환산 계획으로 1,800만원 한도 초과를 판정한다. 실제 해당 연도 납입 이력·납입개월을 반영하는 별도 수정이 필요하다.
2. **국민연금 지급개시일**: 실제 퇴직일보다 앞선 연금 개시일은 기존 공통 조회 검증에서 차단된다. 국민연금에 맞는 별도 날짜 검증 범위를 후속 승인 작업으로 다뤄야 한다.

수익률 5%/7%/8%, 금융 계산식, 날짜 규칙, 데이터 모델, 신뢰도 판정 및 미검증 급여 자동 계산 비활성화는 모두 그대로다. 커밋·푸시는 수행하지 않는다.
