# IRP·연금저축 조사 및 시뮬레이션 설계

조사 기준일: 2026-11-07(한국). 공식 자료를 웹에서 확인했다. 아래의 현행 일반 규정과 미래 투자 가정을 구분한다. 확률·수익 보장·공식 지급액 정확성 인증을 제공하지 않는다.

## 1. 현행 규정과 공식 출처

규정별 기준은 연결한 조문과 국세청 안내에 대조했다. 법령 사이트의 인쇄·연결 페이지는 서로 다른 개정본을 보여줄 수 있으므로 전체 법률의 모든 조문이 2026년 11월에 동일한 버전이라고 단정하지 않는다. 시행령 연결 본문은 2026-10-01 시행 표기를 직접 확인했다. 향후 시행 예정인 이 한도·공제율 변경을 확정할 공식 공포 자료는 이번 조사에서 확보하지 못했다. 이는 향후 개정이 없다는 뜻이 아니다. 장래 연도 결과는 **현재 확인 규정을 고정한 시나리오**이며 미래 적용 세법을 확정하지 않는다.

## 2. 연금 수령·연금 외 수령

[국세청 연금계좌 과세 체계](https://g.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7885&mi=6605) 및 시행령 제40조의2 제3~5항을 확인했다. 일반적으로 55세 이후 개시 신청, 가입 후 5년 경과, 연금수령한도 내 인출이 필요하다. 이연퇴직소득이 있는 계좌는 가입 5년 요건 예외가 있다. 일반 연금수령한도는 `평가액 ÷ (11 - 수령연차) × 120%`이며 11년차 이후에는 해당 한도식을 적용하지 않는다. 2013년 이전 가입·승계 등은 별도 경과규정을 확인해야 한다.

[국세청 연금소득 세율 안내](https://nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7888&mi=6608)에 따르면 일반적인 세액공제 원금·수익의 사적연금 국세 원천징수율은 70세 미만 5%, 70~79세 4%, 80세 이상 3%다. 종신계약은 2026-01-01부터 3%로 안내된다. 이연퇴직소득은 별도 퇴직소득세 기준의 70%, 실제 수령 10년 초과 60%, 20년 초과 50%(2026-01-01 적용) 구조이며 일반 개인납입금에 동일 세율을 일괄 적용하면 안 된다.

일반 사적연금 연 1,500만 원 기준(2024년부터, 이전 1,200만 원)과 종합과세·선택 분리과세, 부득이한 인출 예외도 확인해야 한다. 일반 연금 외 수령의 공제 원금·수익에는 기타소득 국세 15%가 적용될 수 있고, 공제받지 않은 본인 원금은 과세제외, 이연퇴직소득은 퇴직소득 과세 체계다. 지방소득세도 별도다.

따라서 앱의 월 인출액은 **세전 가상 인출**이다. 계좌 개설일, 공제 이력, 원천별 원장, 수령연차, 다른 사적연금·종합소득, 연금수령한도를 확보하지 않아 세후 금액·적법한 연금수령 자격은 계산하지 않는다. 기본정보의 생년월일·임용일은 참고 표시하며 계좌 가입일로 대체하지 않는다.

## 3. 퇴직급여 IRP 이전

[공무원연금공단 과세이연 안내](https://www.geps.or.kr/pensionInfo_information_card_irp)를 직접 확인했다. 공단 퇴직수당·퇴직일시금에는 비과세분이 포함될 수 있어 공단에서 IRP로 직접 받는 것과 수령 후 과세대상분을 이전하는 절차를 구분한다. 안내에는 지급 후 60일 이내 이전 및 과세이연 신고·증빙 절차가 있다. 원천징수영수증의 과세대상액은 실제 지급 총액과 다를 수 있다.

공무원·사학교직원의 퇴직수당을 근로자퇴직급여보장법상 법정 퇴직급여와 동일하게 간주하지 않는다. 사학연금·급여별 과세대상액·수령일·금융회사 취급 조건 검증이 부족해 **이번 버전의 이전 계산 및 비교는 비활성화**한다. 검토 금액·급여 종류·이전일·수익률은 별도 메모 입력으로만 유지하며, 기존 퇴직수당·IRP 잔액·개인 납입원금·공제대상액 어디에도 더하지 않는다. 결과의 이전 금액은 null이다.

## 4. 구현된 계산 범위

### 적립 모델

- 계좌별 현재 평가금액, 연간 개인납입액, 월/연 납입, 연 수익률·수수료, 납입 종료일을 독립적으로 기록한다. 미선택 계좌는 명시적으로 제외하고, 선택 계좌의 빈 금액은 0원으로 대체하지 않는다.
- 기준일 이후 완성된 기념일 개월만 계산한다. 말일은 원래 기준일에 고정해 해당 월 말일로 보정한다. 부분 월은 제외하고 마지막 계산일을 표에 표시한다. 최대 적립 60년.
- 월 수익 배수 `g=(1+r/100)^(1/12)`, 월 수수료 배수 `h=(1-f/100)^(1/12)`. 매월 `round(round(B×g)×h)+월납입액` 순서다. 이는 가정한 수수료 모델이며 실제 상품의 징수 기준을 재현하지 않는다.
- 배수는 10^-12 정밀도로 정수화하고 BigInt 곱셈 후 각 단계에서 원 단위 사사오입한다. 안전 정수 범위 초과는 계산 불가. 연 수익률은 -90~100%, 수수료는 0~20%의 시뮬레이션 입력 범위이며 법정 제한이 아니다.
- 월납입은 연간액을 정수 12분할하고 나머지 원을 앞 회차에 1원씩 배분한다. 연납입은 12개월 뒤 첫 납입, 이후 매 12개월 후납한다. 납입 종료 뒤에는 수익·수수료만 반영한다.
- 초기 평가금액에는 과거 원금·수익이 섞일 수 있으므로 총 역사적 납입원금이라고 부르지 않는다. 초기 잔액, 향후 납입원금, 이후 투자손익을 구분한다.
- 보수적·기준·낙관적 값은 사용자가 직접 입력한다. 시나리오는 양 계좌 수익률만 같은 값으로 대체하며 재투자 수익률·수수료는 유지한다.

### 공제·재투자 모델

일반 국세 공제 대상액 `min(9,000,000, IRP개인납입 + min(연금저축개인납입, 6,000,000))`. 이론상액은 대상액 × 12% 또는 15%이며 원 미만은 버린다. 실제 신고 세액의 끝수 처리·지방소득세 정산까지 검증한 것은 아니다. 사용 가능액은 사용자 확인 남은 국세와 이론상액 중 작은 값이다. 실제 현금 환급액은 원천징수·다른 공제 등에 달려 있으므로 자동 확정하지 않는다.

연간 계획 공제액과 월별 미래 납입을 달력 연도로 모은 공제액을 별도로 보여준다. 기준일 이전의 기납입액은 포함하지 않으며 첫해가 12개월보다 짧으면 공제액도 달라진다. 소득·세액 여력·규정은 매년 동일하다는 사용자 가정이다. 근로소득/종합소득 구분·범위 확인이 없으면 공제액은 계산 불가이나 기본 투자 모델은 사용할 수 있다.

환급 현금은 `min(해당 연도 조건부 공제액, 사용자 확인 연간 국세 환급 현금 상한)`을 다음 해 선택 월의 기준일 기념일에 받는다고 가정한다. 재투자 비율만큼 일반 투자계좌에 넣고 나머지는 현금으로 보유한다. 재투자하지 않는 비교도 같은 환급 현금을 0% 현금으로 보유하므로 원금 차이가 수익 효과로 오인되지 않는다. 퇴직 뒤 예정된 환급은 현재 자산에 넣지 않는다.

일반 투자계좌 재투자에는 추가 연금계좌 세액공제가 없다. **IRP/연금저축으로의 재투자는 연도별 납입한도·추가 공제의 반복 적용을 검증하기 전까지 선택 불가**다. 일반 계좌 투자소득세·거래비용은 미반영이므로 재투자 결과도 세전이다. 재투자 체크를 끄면 환급 현금 모델 자체를 비교에서 제외한다.

### 인출 모델

퇴직일부터 수령 시작일까지 계좌별 동일 수익률·수수료로 성장시킨다. 첫 인출은 수령 시작일 한 달 뒤. 기간 1~40년. 월말 순배수 `a=g×h`, 월 인출액 `floor(B×(a-1)/(1-a^-n))`, 0% 순수익이면 `floor(B/n)`이다. 각 월 실제 잔액은 위 원 단위 모델로 계산하고 자동 일정액의 마지막 회차는 잔액을 정산한다. 선택한 희망 월 인출액이 있으면 잔액까지만 지급해 고갈 이후 0원 지급을 표시한다. 미입력 금액을 0원으로 정한 것이 아니라 실제 계산상 고갈을 뜻한다. 수령액과 잔여자산 월별 표·소진일을 제공한다.

## 5. 검증과 미확인 사항

[생명보험협회 2026 변액보험 교재](https://exam.insure.or.kr/upload/upfile/common/recent/varisu_recent.pdf?dt=1772594506437)의 PDF 126번째 페이지(0 기준 125)에 국세 한정 세액공제 사례가 있다. 종합소득 4천만/6천만 원일 때 연금저축/퇴직연금 납입(만원)이 0/900이면 공제135/108, 200/700이면135/108, 700/200이면120/96, 900/0이면90/72다. 8개 수치와 엔진 결과를 비교한다. 협회 공식 발행 교육 사례이며 **국세청의 앱 검증·실제 신고 정답 인증이 아니다**. 세율·한도는 국세청 및 법령과 별도로 대조했다.

수학 테스트와 세법 범위 검증을 구분한다. 음수·0%·0원·0개월·월/연 납입·부분 월·중도 납입 종료·계좌 합산·수수료·공제 한도·소득 경계·남은 국세 부족·환급 재투자 ON/OFF·추가 공제 방지·이전 금액 미가산·인출 고갈·원 단위 안전 범위를 검사한다. 브라우저에서는 기존 메뉴·기본정보 유지와 IRP 입력·결과·그래프·모바일 너비·입력 유지·이전 차단을 확인한다.

미확인: 개인별 IRP 개설 자격, 계좌 개설·공제 이력, 실제 환급 현금 정산, 다른 계좌·ISA·주택 등 특례, 미래 세법, IRP 이전 개별 조건, 지방소득세 및 연금 세후액, 상품별 수수료·투자 제한·실현 수익률. 이를 확정값으로 표시하지 않는다.

## 6. 파일 구조와 다음 우선순위

검사 기록(2026-11-07): 타입 검사 통과, 단위 테스트 84/84 통과(신규 IRP 14개 포함), 전체 데스크톱·모바일 브라우저 테스트 28/28 통과. 이후 환급 재투자 UI 검증을 보강하고 해당 브라우저 4/4를 재검사해 통과했다. 최종 타입 검사와 프로덕션 빌드도 통과했다. 전체 브라우저 최초 실행에서 기존 공적연금 항목 1건이 실패했으나 전체 재실행에서 통과했다. 로컬 Edge에서 런타임 오류·320~1440px 가로 넘침·메뉴 이동 보존을 확인했다. 이러한 통과는 개인별 세금 신고나 실제 금융상품 지급액의 정확성 인증이 아니다.

`irp-input.ts`는 계좌·세금·시나리오 입력 계약, `irp-validation.ts`는 입력 검증, `irp-tax.ts`는 일반 국세 공제와 이전 차단, `irp-simulation.ts`는 독립 순수 계산, `irp-panel.tsx`는 화면이다. 기존 공적연금·퇴직수당·교직원공제회 계산은 변경하지 않는다. 메뉴 전환 상태는 부모 컴포넌트에서 보관하며 새로고침 시 초기화된다. 서버·Supabase·외부 API로 금융 입력을 전송하지 않는다.

다음 우선순위는 원천별 연금 원장·계좌 개설일과 수령한도 검증 → 실제 연말정산 여력·현금 환급 구분 개선 → IRP 재투자 납입한도와 반복 공제 검증 → 공적연금 퇴직수당 이전의 과세/비과세 분리 및 금융회사 확인이다. 이번 단계에서는 자동 진행하지 않는다.
