# 교사 은퇴 계산 고도화 계획 및 검증 기록

작업 범위: 2026-11-08, 최초 요청의 1~4단계 및 후속 승인된 5~7단계 구현. 1~6단계는 각각 후속 사용자 지시로 커밋·Push했다. 이번 7단계는 커밋·Push·배포하지 않으며 8단계는 진행하지 않는다.

7단계 진행·완료 기록: [은퇴설계 종합 분석·규칙 기반 조언](retirement-strategy-analysis.md). 중단 당시 작성된 분석/조언/화면 코드를 보존하여 확장했다. 기존 1~6단계 엔진을 재사용하고 선택 생활비·전후 타임라인·월액 비교·조건부 자산 활용·조언 5개 및 06 데이터 연결을 검증한다.

6단계 구현 기록: [IRP·연금저축 수령 조건·세법 근거·검증](account-receipt-conditions.md). 계좌별 선택 가입일, 실제 이연퇴직소득 확인 예외, 독립 수령한도·재원별 세금 안내 및 05·06 연결을 추가한다. 기존 적립 엔진은 유지한다.

5단계 완료 기록: [공적연금 자동 추정 구현·공식 근거·검증 결과](public-pension-estimation.md). 기본정보만으로 객관적 평균소득을 만들지 않으며, 공단 기초자료 또는 명시적 고정소득 시나리오가 있는 지원 범위에서 추정한다. 단위 226개·브라우저 50개 통과, 프로덕션 빌드 성공. 개인별 외부 금액 검증은 미완료다.

## 5단계 추가 작업 계획 (2026-11-08 사용자 승인)
1. 기존 조회값 검증을 재사용하고 공무원/사학/국민연금 자동 추정 경로를 별도로 추가한다. 01~04 계산은 유지한다.
2. 호봉만으로 평균보수·평균기준소득·소득재분배·이행률을 확인할 객관적 자료가 없어 기본정보만으로 금액을 만들지 않는다. 기본정보만으로 산정 가능한 인정기간 시나리오·정상 개시조건·공백을 먼저 표시한다.
3. 상세 설정에서 공단 확인 평균소득·재분배 반영소득·이행률 등 필요한 기초자료를 선택 입력받아 월연금을 자동 산출한다. 현재 소득을 쓰는 경우 사용자가 명시적으로 동의한 고정소득 시나리오로만 사용한다. 누락 계수에 임의 기본값을 넣지 않는다.
4. 직역연금은 세 법정 구간·연도별 지급률·30년 재분배·인정기간 상한·종전 1.9% 비교 제한을 검증한다. 사학 근거를 별도 연결한다. 확인 못한 구법/특수경력 조건은 이유와 함께 제한한다.
5. 국민연금은 교사 임용과 별도의 실제 납부 시작월/종료월을 받고, 가입시기별 비례상수·2026 A값·재평가된 B값·10년 요건·상한을 별도 계산한다. 공무원 군 산입 상태를 국민연금 크레딧으로 변환하지 않는다.
6. 정상 조건 충족 예상일·최초 지급대상월·조기수령 가능 조건을 구분한다. 조기를 자동 선택하지 않는다. 05 및 06에 금액·가정·신뢰도·공백·누락 정보를 연결한다.
7. 세 제도/임용시기/퇴직유형/군복무/소득 누락 및 추가/퇴직일 변경을 단위·브라우저 테스트하고 TypeScript·프로덕션 빌드를 실행한다. 공식 숫자 검증과 산술 검증을 구분한다.

5단계까지만 구현한다. 6단계 자동 진행, 커밋·Push·배포, 서버 저장/로그인/DB 추가 없음. 아래 1~4단계 기록은 당시 작업 기록으로 보존한다.

## 기존 조사와 코드 차이
- `pension-calculation-research.md`는 명퇴 68%·잔여기간 구간, 퇴직수당 지급률·33년 상한을 조사했지만 현행 별표 끝수·개인별 공식 사례 검증이 미완료다.
- 간편 화면은 명퇴 자격/선정 선택과 두 수당 직접 입력을 요구한다. 2026 봉급표가 이미 있으나 계산에 연결되지 않았다.
- IRP/연금저축은 기준일의 월 기념일마다 납입하며 부분 월을 제외한다. 실제 월말/12월말 납입으로 변경해야 한다.
- 상세/레거시 엔진과 공제회 계산은 유지한다. 현재 사용자 변경 `next-env.d.ts`를 보존한다.

## 전체 순서
1. 계좌별 월/연 납입, 달력 월말/12월말 현금흐름, 부분 기간 복리, 실제 납입 연도별 한도 및 환급 재투자 처리.
2. 명퇴 자격/선정 및 명퇴금 직접 입력을 기본 화면에서 제거.
3. 현행 별표와 교원 봉급표를 확인하고 공무원 일반 호봉제 교원 명퇴수당의 2026 봉급표 기준 조건부 추정 구현. 사학/국민연금에 공무원 산식 자동 적용 금지.
4. 공무원/사학 퇴직수당의 검증된 범위 구현. 소득은 호봉에서 임의 추정하지 않고 기초 소득자료만 선택 입력. 인정기간·군복무 제외·구법 제한·세전 합계 조건 명시.
5. 공적연금 제도별 자동 추정 (다음 지시 이후).
6. 계좌 수령 요건 (다음 지시 이후).
7. 종합 조언/전후 그래프 (다음 지시 이후).
8. AI 요청문 고도화 (다음 지시 이후). 이번 변경으로 기존 문구가 잘못되지 않도록 정합성만 수정.
9. 타입 검사, 기존 및 경계 단위 테스트, 데스크톱/모바일 E2E, 프로덕션 빌드.

## 검증 원칙
공식 산식·입력 가정·실제 지급 심사를 분리한다. 현재가치란 2026 봉급표 가격 고정을 뜻하며 할인현금흐름 결과는 아니다. 미래 봉급 인상·세금·감액·예산·선정은 확정하지 않는다. 공식 개인별 지급액 대조 전 정확한 실지급액으로 표시하지 않는다. 미지원/누락은 0원과 구분한다. 각 단계의 출처·구현·테스트·남은 한계는 아래 추가한다.

## 1단계 구현: 계좌별 납입과 복리
- `src/lib/simple/account-schedule.ts`: 기준일 다음 날부터 퇴직일 당일까지 실제 달력 월말에 월납, 12월 31일에 연납한다. 기준일 당일은 현재 평가액에 포함된 것으로 보아 재납입하지 않는다. 첫해 연납도 12월 전에 퇴직하면 0회이고, 12월 말까지 재직하면 연액 전체 1회다. 연액을 12로 나누지 않는다.
- `calculation.ts`: 초기잔액과 각 납입 건별 미래가치를 구해 원 단위 반올림 후 더한다. 유효 연 수익률 7%/8%, ACT/ACT(각 연도 실제 일수/365 또는 366) 복리다. 부분 월에도 잔액은 퇴직일까지 성장한다. 날짜 계산은 UTC로 고정하여 현지 시간대/DST의 영향을 피한다. 공제회는 기존 완료 월 방식 그대로다.
- 연도별 실제 예정 개인납입을 두 계좌 합산하여 1,800만원 초과를 차단한다. 올해 기납입, 다른 계좌, 이전 특례는 미확인이므로 실제 잔여한도 보장은 아니다.
- 환급 재투자: 선택 입력인 근로소득 연 총급여와 공제 전 소득세 여력이 모두 있어야 계산한다. 기존 `pensionTaxCredit`를 재사용한다. 연금저축 600만원/합산 900만원, 국세 12%/15% 및 소득세 여력 한도를 적용한 **공제 가능액 시나리오**다. 실제 환급액으로 부르지 않는다. 다음 해 5월 31일에 IRP로 넣고 퇴직 이후 날짜는 제외한다. 재투자금도 납입 연도의 개인납입 및 다음 공제 계산에 포함한다. 재투자 포함 한도 초과는 전체 재투자 시나리오를 적용하지 않고 기본 결과를 유지한다.
- 소득과 세액 여력은 매년 동일하다는 가정이며 지방세·올해 기납입·다른 공제·실제 환급 시기 차이는 미반영이다. 입력이 없으면 미반영 상태를 유지하며 0원으로 확정하지 않는다.
- 세액공제 공식 근거: [국세청 연금계좌 세액공제](https://www.nts.go.kr/nts/cm/cntntsView.do?cntntsId=7875&mi=2227), 이번 재확인의 보완 출처인 [국세청 홈택스 종합소득세 공제 안내](https://mob.tbht.hometax.go.kr/jsonAction.do?actionId=UTBRNAAT31F001&subMenuId=01). 후자에서 4,500만원/근로소득만 있으면 총급여5,500만원, 12%/15%, 연금저축600만원/퇴직연금 합산900만원을 재확인했다. 전자 본문은 이번 도구 열람에서 오류가 발생했다. 기존 `docs/irp-pension-research.md`의 공제·실제 환급 구별을 유지한다.

## 2~3단계 구현: 명예퇴직수당
- 기본 화면에서 지급 자격/실제 선정 선택 및 명퇴수당 직접 입력을 제거했다. 기존 숨겨진 값은 자동 계산에 사용하지 않는다. 6개 메뉴·CSS·공제회 기능은 유지했다.
- `src/lib/simple/benefit-estimates.ts`: 공무원연금 가입 일반 국공립 유·초·중·고 정규 호봉제 교원이라는 명시적 신분 가정하에 임용일부터 계속 재직/제한 없는 정기승급을 가정한다. 20년 미달 또는 정년보다 1년 이상 이르지 않은 퇴직은 금액을 만들지 않는다. 임용 전 병역·합산이 있어 20년을 충족할 수 있는 경우에도 앱이 승인 이력을 알 수 없어 기관 확인 사유를 표시한다.
- 퇴직 다음 달 1일부터 정년 월말까지 잔여월수를 산정한다. 월말이 아닌 직접 수정 정년일은 끝수 규칙을 임의 적용하지 않고 미지원으로 안내한다.
- `F`: 예상 퇴직호봉에 해당하는 **2026년 교원 봉급표** 봉급. `M=F×68%`. 잔여 12~60개월은 `M/2×n`, 61~120개월은 `M/2×[60+(n−60)/2]`, 120개월 초과는 `M/2×90`. 정확히 12개월은 포함, 12개월 미만은 일반 요건 미충족으로 금액 미표시. 근가호봉·특별가산·특별승진·대학/연봉제/시간제는 미반영이다.
- 명퇴수당에 법정 재직·조기퇴직의 기본요건 검사를 적용하지만 징계·수사·기수령 등 제한, 신청·예산·인력수급·선정은 확인되지 않는다. **조건부 금액/지급 미확정**을 결과에 표시한다. 실제 선정이 확인되었다고 간주하지 않는다.
- 사학은 학교 정관과 관할청 시행계획을 확보하지 않아 자동 명퇴수당을 지원하지 않는다. 국민연금 가입을 교육공무원 신분의 증거로 사용하지 않는다.

## 4단계 구현: 퇴직수당
- 공무원과 사학의 별도 공식 출처를 연결하고 **2010년 이후 신규 임용자의 기본식**을 지원한다. 국민연금 가입자에게 이 급여를 적용하지 않는다.
- 2026년 기준 퇴직수당용 기준소득월액을 선택 입력받는다(금액 UI는 만원, 내부 원). 호봉·최종봉급에서 임의 비율로 역산하지 않는다. 퇴직일까지 2026년 소득 가격 수준이 유지된다는 가정이며 실제 최종기준소득월액 예측이 아니다.
- 인정기간 미입력 시 임용월부터 퇴직일 전날이 속한 월까지 중단 없는 재직으로 가정한다. 선택적으로 공단 확인 퇴직일 기준 수당 인정 개월을 입력해 조정할 수 있다. 퇴직일 변경 시 재입력을 요구한다. 임용 전 병역·과거 합산은 자동 가산하지 않는다. 휴직/정직 등의 법정 감축·기수령·과거 적용례는 공단 확인기간으로 조정해야 한다.
- 총 인정기간 1년/5년/10년/15년/20년 경계에서 각각 6.5%/22.75%/29.25%/32.5%/39%를 선택하여 전체 인정연수에 곱한다. 누진 구간식이 아니다. 계산기간은 최대 396개월(33년). 1년 미만은 0원이 아니라 일반 지급요건 미충족으로 표시한다.
- 산식: `기준소득월액 × min(인정개월,396)/12 × 지급률`. BigInt 유리수 계산 후 원 미만 버림. 이는 앱 표시 규칙이며 공단의 법정 끝수까지 검증한 결과가 아니다.
- **2009년 이전 재직분은 미지원**: 별도 최종보수월액 환산과 각 제도의 경과규정·기간 배분 검증이 남았다. 이 경우 2010년 이후 기본식을 전 기간에 적용하지 않고 필요한 구기간 소득/경과검증 사유를 표시한다. 기준소득월액을 입력해도 차단한다. 실제 퇴직수당 자체 입력을 요구하는 방식으로 돌아가지 않는다.
- 두 수당 모두 같은 퇴직일·2026년 가격·세전으로 계산 가능한 경우에만 합산한다. 세후·실지급액·선정 확정 합계가 아니다.

## 최소 추가 입력
- 월/연 납입은 각 계좌에서 선택한 주기의 금액만 입력한다. 전환 전 월액/연액은 각각 보존한다.
- 명퇴수당: 기존 기본정보만 사용. 기본요건 또는 적용 신분을 확인할 수 없는 경우 사유를 안내한다.
- 2010년 이후 퇴직수당: 공단 확인 2026년 기준소득월액 1개. 필요할 때만 퇴직일 기준 수당 인정 개월 추가.
- 환급 재투자 효과: 원하면 가정 연 총급여·공제 전 소득세 여력 2개. 미입력해도 기존 기본 적립 결과를 제공한다.

## 계산 사례 (공식 실지급 사례가 아닌 수학/가정 검증)
- 봉급표 30호봉 4,826,800원, 명퇴 2031-08-31, 정년 2042-08-31: 잔여 132개월, `4,826,800×0.68÷2×90 = 147,700,080원` 세전 조건부 추정.
- 임용 2010-03-01, 퇴직 2031-08-31, 소득 6,000,000원 고정: 258개월, `6,000,000×258/12×0.39 = 50,310,000원` 세전 조건부 추정. 33년 상한 예시는 `6,000,000×33×0.39 = 77,220,000원`.
- 2026-01-01부터 12월31일까지 잔액0/연600만원 계획, 연7%: 월50만원은 12회로 6,191,064원, 연600만원은 12월31일 1회로 6,000,000원이다. 총 원금은 같고 월납은 일찍 납입한 기간의 투자손익이 더해져 미래가치가 다르다.
- 2026-11-08부터 2027-02-27까지 월납: 11월30일·12월31일·1월31일만 포함. 2월말은 퇴직 후이므로 제외한다. 같은 기간 연납은 2026년12월31일 1회다.

## 기존 결과와의 충돌 및 정합성
- 공제회/상세·레거시 엔진은 수정하지 않았다. 기존 미검증 엔진을 검증 완료로 변경하지 않았다.
- 간편 IRP/연금저축의 과거 월 기념일/부분 월 제외 결과는 의도적으로 달라진다. 기존 테스트의 원금0·1회 납입 기대는 유지하고 월말 납입 이후 잔여일 이자를 새 기대에 포함했다.
- 명퇴 선정/직접 금액을 전제로 하던 테스트는 자동 추정과 지급 미확정 검증으로 변경했다. 제거된 과거 조회값과 선정 값은 자동 계산에 반영되지 않는다.
- 기존 종합 및 AI 요청문에 자동 수당의 세전/2026년 가격 가정, 새 납입주기와 부분 기간 설명을 연결했다. 새 조언·공적연금 엔진·5~8단계 기능을 개발한 것은 아니다.

- 브라우저 E2E: `npm run test:browser` 최종 실행 **40/40 통과**(MS Edge, 데스크톱20/모바일20). 새 납입주기 전환·입력값 보존·환급 시나리오·자동 수당·선택 제거·사학/국민연금 분리·6개 메뉴·만원 표시·정보 외부 전송/저장 없음·320px 폭 등을 확인했다. 첫 실행의 과거 입력 흐름/부분 월 기대값 및 엄격 선택자 실패를 수정하고 전체 재실행했다. 새 수당/납입 화면 스크린샷을 확인했다.

- `git diff --check` 통과. 실행한 테스트 개발 서버만 종료했다. 커밋·Push·배포·DB/로그인 추가는 하지 않았다. 사용자가 작업 시작 전 갖고 있던 개발용 `next-env.d.ts` 경로 변경은 유지했다.
- 정확한 개인별 공단/교육청 지급액과 대조하지 못했다. 금액은 조건부 계획 도구로만 공개할 수 있으며, 정확한 법정/세후 실지급 계산기로 공개할 수 없다. 현행 별표 원본 전체·끝수·구법 재직분·개인별 소득환산·심사/제한·공식 지급 사례의 검증이 남아 있다.
