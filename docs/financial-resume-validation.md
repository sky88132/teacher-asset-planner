## 2. 월연금 미표시 원인과 현재 동작

이전 `hasIncome`은 소득자료가 아닌 임용일·퇴직일 확인값도 실제 소득으로 취급했다. 날짜 확인만 해도 교원 시뮬레이션이 실행되지 않고 공단 확인 소득 전용 엔진의 필수자료 부족 상태로 전환되는 것이 원인이었다. 이 조건은 현재 파일에서 이미 제거되어 있다.

현재 데이터 흐름은 기본정보 → 매월 호봉 → 봉급표 연3% 및 수당 → 연도별 보수 → 재직월 가중평균 소득 기초 → 개인소득/재분배소득 및 적용비율 → 기존 공무원연금 구간식 → 기준·90/110% 소득 민감도 → 05·06이다. 실제 과거 소득이 없다는 사실만으로 지원 가능한 표준 교원 모델을 차단하지 않는다. 실제 소득·계수를 직접 입력하거나 공식 조회액을 입력한 경우에는 해당 입력 경로의 우선순위와 유효성 검사를 유지한다.

일반 국공립 호봉제·2010년 이후 신규 임용·연속 경력·과거 호봉 역산 가능 등의 기존 지원 범위에서 참고 월액을 계산한다. 실제 사용자의 현재 입력은 수집하지 않았으므로 특정 사용자의 미표시 원인을 새로 단정하지 않는다. 지원 밖 조건은 구체적 이유를 표시하며 정상 개시일과 공백기간은 별도로 유지한다.

## 3. 실제 수정과 합계 상태

이번 재개에서는 기존 금융 계산·화면 코드에 추가 변경을 하지 않았다. 이미 완료된 수정을 보존하고 시스템 Node.js로 검사하며 이 재개 보고서를 추가했다. 오류를 재현하지 못한 상태에서 정상 로직을 불필요하게 다시 작성하지 않았다.

04는 명예퇴직수당 → 퇴직수당 → 참고 합계 순서이며 개별 금액이 기본 노출된다. 근거만 접혀 있다. 과거 ‘완전한 합계 확인 불가’ 카드가 소스에서 제거되어 있다. `benefitReference`가 퇴직일·가격연도·세전 기준을 함께 선택해04·05·06에 전달한다. 미래 명목과2026 고정 기준을 섞지 않고 원 단위 합계 후 만원 정수로 표시한다. 월연금은 일시금 금융자산에 합산하지 않는다.

## 6. GitHub 저장 가능 여부

현재 코드가 로컬 파일로 보존된 상태다. README에는 기존 main과 Vercel 사용 의도가 적혀 있지만 실제 `.git`·원격 URL·브랜치·접근 권한은 이 복사본에서 확인되지 않는다. 따라서 기존 GitHub 저장소에 바로 커밋/Push할 수 있다고 판정할 수 없다. 원래 저장소의 checkout과 원격 정보를 확인한 뒤 변경 파일을 비교·옮기는 작업이 별도로 필요하다. 이번에는 Git 초기화·clone·커밋·Push·Vercel 배포를 하지 않았다.
