# 간편 계산 6메뉴 개편 및 검증 기록

확인일: 2026-11-08. 설정 버전: `simple-2026-11-v1`. 기존 프로젝트에서 진입 화면만 교체하고 기존 금융·AI 엔진과 조사 문서는 보존했다. 인증·DB·Supabase·외부 AI API·지속 저장을 도입하지 않았다.

## 1. 영향 범위와 구조

기존 `planner.tsx`가 7개 화면과 상세 상태를 소유했다. 기존 입력 타입은 학교 구분·다수 상품·시나리오·세액·생활비가 연결되어 있어 그대로 축소하면 기존 엔진의 의미를 바꿀 수 있었다. 따라서 기존 코드는 보존하고 간편 모드 모델·검증·어댑터를 별도로 두었다.

- 현재 진입: `src/app/page.tsx` → `src/components/simple-planner.tsx`.
- 모델/설정: `src/lib/simple/model.ts`, `config.ts`.
- 검증/계산: `validation.ts`, `calculation.ts`. 기존 공제회 적립·가상 인출, IRP 원 단위 성장, 금액·달력 검증을 재사용한다.
- AI: `src/lib/simple/prompt.ts`가 새 결과의 허용 목록만 변환한다. 기존 금액 익명화·개인정보 패턴·질문 검토 함수를 재사용한다.
- 화면: `src/components/simple/`의 profile/assets/benefits/overview/prompt/shared.
- 모든 입력과 AI 편집본은 최상위 React 상태에 둔다. 메뉴 전환은 저장을 수행하지 않는다. 계산 기준일은 브라우저에서 한국 날짜로 정해 해당 세션에서 고정한다. 서버/브라우저 시계 차이가 초기 화면 불일치를 만들지 않도록 클라이언트 준비 후 계산한다.

최종 메뉴는 교사 기본정보 → 교직원공제회 → IRP·연금저축 → 퇴직급여 계산 → 은퇴설계 종합 → AI 분석 요청문이다. AI는 기본정보만 유효하면 다른 메뉴를 입력하지 않아도 생성할 수 있다.

## 2. 제거·추가된 입력

학교 구분·학교 기본 연금 선택, 단순 군복무 경험 체크, 휴직/경력 합산 상세, 기타 공제회 상품, 수익률·수수료·납입 종료일·계좌별 퇴직일·수령 시점, 생활비·물가·연령별 현금흐름 화면을 간편 UI에서 제거했다. 이전 컴포넌트·모듈은 삭제하지 않았다.

연금제도는 공무원/사학/국민 중 직접 선택한다. 현재 호봉·승급월·군 산입 상태·배타적인 정년/명퇴·공통 퇴직일을 추가했다. 정년 수동 수정은 보조 기능이다. 국민연금의 군복무 크레딧은 별도 안내로 바뀌며 공무원 산입 상태를 적용하지 않는다. 승인 여부만으로 인정기간을 더하지 않는다.

금융 기본 입력은 공제회 잔액·월 납입·분할 선택(선택 시 기간), IRP/연금저축 각각 잔액·월 납입과 재투자 체크뿐이다. 수당과 월연금의 공식 조회액은 접힌 선택 입력으로 제공하며, 조회일·세전/세후·출처와 해당 퇴직일로 조회했다는 확인을 받는다. 퇴직일 자체를 반복 작성하지 않는다.

## 3. 공식 근거 확인과 적용 범위

아래는 확인한 사실과 앱의 가정을 구분한 기록이다. 금융기관 지급액 정답 검증 완료를 의미하지 않는다. 연결 페이지 중 일부는 동적 본문 때문에 다른 공식 조문 링크로 대조했다.

### 정년·호봉

- [교육공무원법 제47조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032085735): 2026.10.2 시행 본문에서 일반 정년 62세 및 학기말 규칙을 확인했다. 앱은 학교급·신분을 묻지 않아 **일반 초·중등 규정 적용 가정**으로만 날짜 후보를 제공한다. 사학 가입은 국공립 교원 신분 확인이 아니며 대학·사립 정년은 실제 기관 확인이 필요하다.
- [민법 제160조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0160&lsiSeq=284415&urlMode=lsScJoRltInfoR): 해당일 없는 월의 말일 원칙을 참고했다. 윤일 출생은 62세 연도의 2월 말일 후보를 반환하는 경계 테스트를 포함했다. 개별 인사상 실제 정년일의 최종 확인은 대체하지 않는다.
- [공무원보수규정 제13조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027304115): 2026.10.2 시행 정기승급의 일반 기간을 대조했다. 매년 선택 월 1일에 1호봉, 승급 제한 없음이라는 **조건부 일정**만 계산한다. 현재 호봉은 오늘 기준이므로 오늘 또는 이미 지난 승급일을 다시 적용하지 않는다. 실제 발령·휴직·징계·특별승급·사학/국민연금 대상자의 보수 적용은 확정하지 않는다.
- [인사혁신처 2026 봉급표 별표11](https://www.mpm.go.kr/mpm/info/resultPay/bizSalary/2026/): 1~40호봉 값을 대조했다. 테스트의 22호봉 3,733,600원·40호봉 6,205,700원은 이 표의 숫자다. 표상 40호봉까지만 참고하며 근가호봉은 미반영이다. 미래 봉급표·인상률·기준소득월액·명퇴 산정 봉급액으로 사용하지 않는다.

### 군복무

- [공무원연금법 시행령 현행 본문](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=82190): 2026.10.2 시행 제18조·제20조·제23조를 대조했다. **요청문에 언급된 제20조는 재직기간 합산절차이고, 임용 전 복무기간 산입절차는 제23조다.** [정부24 산입 신청](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=13110000035)과 함께 안내한다. 승인과 소급기여금 완납을 같은 값으로 처리하지 않는다.
- [사학연금법 제31조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1030483837), [사학연금 시행령 제17조의3](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=03&joNo=0017&lsiSeq=290433&urlMode=lsScJoRltInfoR): 2026.10.2 시행 임용 전 복무기간과 신청·결정 절차를 별도로 확인했다. 앱은 상태만 기록하며 재직개월·수당 인정기간을 계산하지 않는다.
- [국민연금공단 개혁 안내](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0104M0.do): 2026.1.1 이후 군복무 종료자의 군복무 크레딧 확대와 종전 적용 조건을 확인했다. 앱은 종료일·기존 인정 조건을 입력받지 않아 가입월수를 추가하지 않으며 해당 기관 안내만 제공한다.

### 교직원공제회

- [장기저축급여](https://www.ktcu.or.kr/PPW-FIA-100100): 2026.7.1 기준 연복리 5%는 변동·세전이며 과거 납입분에는 별도 급여 구조가 있다. 이번 고정 미래 5% 모델은 공식 정산급여금·특별가산금까지 재현한 산식이 아니다.
- [분할급여금](https://www.ktcu.or.kr/PPW-FIA-300100), [신청안내](https://www.ktcu.or.kr/PPW-CSC-100201): 가입자·퇴직 사유, 세후 퇴직급여금 이내 최소 500만원·100만원 단위, 원리금 균등 방식, 5~30년, 지급일 선택과 최초 회차 조건을 확인했다. 앱에서는 매월 25일을 고정 선택한다.
- 실제 전환일은 아직 없으므로 퇴직일을 전환일로 가정하고 한 달 경과 후 도래하는 25일을 보여준다. 예: 2026.3.1 전환이면 4.25, 3.26이면 5.25. 공식 지급일의 휴일 조정은 미반영이다.
- 금액은 기존 **가상** 월 균등 인출 함수다. 날짜 표시는 위 25일 규칙으로 바꾸지만 추가 대기 일수 이자·개인별 세금·끝수 처리·실제 가입 승인까지 검증하지 않았으므로 공식 분할급여금으로 부르지 않는다. 전체 추정 세전 잔액을 사용하는 가상 결과와 실제 세후 가입 가능 금액은 다르다. 이 제한은 화면에도 표시한다.

### IRP·연금저축

- 고정 7%·8%는 사용자 요청에 따른 장기 계획 가정이다. 과거 수익률을 포트폴리오의 확정 실적으로 바꾸지 않는다. 모든 미래 기간에 같은 수익률이며 세금·수수료·환율은 제외한다.
- 2026.9.30 달러 기준 NAV 10년 연평균 총수익률 참고: [SPY 공식 표](https://www.ssga.com/us/en/intermediary/etfs/state-street-spdr-sp-500-etf-trust-spy) 15.18%, [Invesco 공식 ETF 목록](https://www.invesco.com/us/en/financial-products/etfs.html) QQQ 20.91%, [AGG 공식 표](https://www.ishares.com/us/products/239458/ishares-core-us-aggregate-bond-etf) 1.11%를 대조했다. 요청한 QQQ performance 주소는 다른 안내 페이지로 이동하여 운용사 ETF 목록의 같은 분기 NAV 표를 사용했다. 이 숫자는 계산 상수로 사용하지 않으며 개인 투자성과·미래 보장 수익률로 표시하지 않는다.
- [소득세법 제59조의3](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032951711): 2026.7.1 시행 일반 국세 공제율 12%/15%, 소득 조건, 연금저축 600만원·합산 900만원과 과세이연 퇴직소득/계좌 이전금 제외를 대조했다. 실제 환급액에는 세액과 다른 정산 정보가 필요하다.
- [소득세법 시행령 제40조의2 제2항](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033240359): 2026.10.1 시행 일반 개인납입 연 1,800만원을 확인했다. 두 계좌 월 납입 계획의 합이 150만원을 넘으면 간편 모드 결과를 차단한다. 다른 납입·특례·기납입액의 확인을 대체하지 않는다.
- 재투자 체크는 보존하되 소득·결정세액·실제 환급·추가 납입 여력이 없으므로 이론상 공제/재투자 효과를 생성하지 않는다. 불명확한 표준 소득 구간을 임의 선택하거나 0원 환급으로 확정하지 않는다. 이전의 정밀한 조건부 공제·재투자 엔진은 보존했다.
- 위 시행 중 규정만 설명하며 입법예고·미래 연도 예상 세법/봉급 인상을 현재 규정으로 적용하지 않는다.

### 퇴직급여

기존 `pension-calculation-research.md`의 공무원·사학 지급비율/상한 조사와 계산 차단 상태를 유지한다. 이번에 필요한 소득 이력·인정기간·현행 별표·명퇴 적용 신분·선정·경과규정·공식 숫자 사례·절사를 모두 확인한 것이 아니다. 국민연금 가입자에게 공무원·사학 수당을 자동 적용하지 않고 별도 법정 퇴직급여 적용·평균임금·계속근로/DB/DC 정보를 안내한다. 자체 수당 금액은 생성하지 않는다.

## 4. 수학적 계산·합산 계약

완료 월수는 기존 날짜 함수로 산정한다. 연 수익률 r을 `(1+r/100)^(1/12)`로 환산하고 매 계산월 수익 반영 → 원 단위 반올림 → 월 납입 순서다. 1e12 고정소수 비율·BigInt를 쓰는 기존 성장/이자 함수를 재사용하고 안전 정수 범위를 검사한다. 마지막 미완성 월은 제외하며 계산 종료월부터 퇴직일까지 추가 납입·수익이 없다는 가정을 공통 적용한다.

잔액의 과거 원금·수익은 알 수 없으므로 '현재 평가금액 + 향후 납입원금 + 향후 투자손익'으로 표시한다. 현재 잔액만의 미래가치와 추가 납입의 미래가치도 구분한다. 반올림 배분으로 총액과 구성액이 어긋나지 않게 추가 납입 미래가치는 총액과 현재 잔액 미래가치의 차로 정산한다.

퇴직일 변경 시 조회 가정일이 다른 공식 입력은 원문을 보존하되 결과 금액은 null로 무효화한다. 제도 전환 시 다른 제도 금액을 섞지 않는다. 미입력과 실제 0은 구별한다. 두 수당이 유효하고 선정·동일 세금 기준일 때만 수당 합계를 표시한다. 주요 적립금 합계는 공제회+IRP+연금저축이고 월연금·수당·미래 분할 총수령액을 더하지 않는다. 누락 항목이 있으면 완전한 합계를 만들지 않는다.

## 5. 단계별 검사와 테스트 구성

1. 기존 코드·의존 관계를 읽고 새 모델/어댑터를 분리했다. 기존 계산 단위 테스트 129개를 보존했다.
2. 기본정보·정년 후보·호봉 조건부 일정 및 국민연금 예외를 단위/브라우저로 검사한다.
3. 공제회 입력·5%·기간별 분할·매월25일·일시/분할 중복 방지를 검사한다.
4. 계좌별 7/8%·0원·0개월·한도·재투자 미반영을 검사한다.
5. 수당 카드 조건부 노출·선정·세금 혼합·조회일 불일치를 검사한다.
6. 종합의 실시간 결과·구성 그래프·누락 표시를 검사한다.
7. 기본정보만의 6개 목적 요청문·익명화·편집·복사·실패 시 수동 선택·변경 후 재생성을 검사한다.
8. 모바일 320/390/640px와 데스크톱 900/1440px의 전 메뉴 가로 넘침·입력 유지·새로고침 초기화, 외부/쓰기 요청 및 저장소 미사용을 검사한다.

새 수학적/연결 단위 테스트 22개는 공식 급여금의 정답 검증을 대체하지 않는다. 봉급표의 공식 숫자 대조와 시뮬레이션 산술 검증도 구분한다. 기존 7메뉴 UI 전용 브라우저 테스트는 원문 그대로 `tests/legacy-browser/`로 이동하고 현재 6메뉴 브라우저 테스트로 대체했다. 기존 금융 모듈 단위 테스트는 계속 실행한다.

테스트 과정에서 접근성 이름·결과 영역, 누락 오류의 중복 React key, 누락된 앱 아이콘 요청을 수정했다. 금융 입력을 기록하거나 전송해서 해결하지 않았다. 개발 서버의 오류 스택 요청도 없는지 최종 브라우저 테스트로 확인한다. 생성 AI 지문은 메모리 내 원문 JSON으로만 사용하며 화면·로그·요청에 내보내지 않는다.

## 6. 미확인·남은 범위

- 실제 신분·학교 정년, 호봉 승급 제한·근가호봉·향후 봉급표는 입력 없이 확정할 수 없다.
- 공적연금과 두 수당은 공식 조회값 중심이다. 자체 법적 급여 금액 엔진을 활성화하지 않았다.
- 공제회 가입 가능 세후 금액과 공식 세금/끝수/첫 회차 일수 이자를 재현하지 않는다.
- 환급 재투자 실제 효과와 연금계좌 세후 인출은 제공하지 않는다.
- 생활비·소득·은퇴 이후 현금흐름·완전한 명퇴/정년 우열 비교는 이번 간편 UI 범위에서 제외했다. 기존 엔진을 삭제한 것은 아니다.
- AI는 로컬 요청문 생성뿐이다. 개인정보 자동 탐지는 완전하지 않아 수동 검토가 필요하다. 사용자가 외부 AI에 붙여넣는 행위는 해당 서비스로의 전달이다.
- 모바일 브라우저 설정 테스트와 실제 기기 검사는 구분한다. 로그인·영속 저장은 없다.
