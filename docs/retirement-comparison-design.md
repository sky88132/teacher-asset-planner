# 05 명예퇴직·정년퇴직 비교

확인일: 2026-11-07(한국). 기존 디자인과 02·03·04 모듈을 유지하며 시나리오 조합 계층만 추가했다. 금융기관 인증·API·저장소·AI·외부 금융자산·완전한 현금흐름은 추가하지 않는다.

## 정년 적용 범위와 근거

- [교육공무원법 제47조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032085735): 열람본은 시행 2026-10-02, 법률 제21857호. 일반 교육공무원 정년 62세, 고등교육법 제14조 교원 65세 예외 및 3~8월 도달 시 8월31일, 9~다음2월 도달 시 다음2월 말일 규정을 확인했다. 1~2월생은 도달 연도 2월말, 9~12월생은 다음 연도 2월말이다. 2월 말일은 윤년을 반영한다.
- [법제처 12-0189 해석례](https://www.law.go.kr/DRF/lawService.do?ID=324587&OC=unicpla&mobileYn=Y&target=expc&type=HTML)는 3월1일생의 8월31일 퇴직을 설명한다. 정년 도달일을 임의로 생일 전날로 옮겨 학기를 바꾸지 않는다. 원 질의는 국립대 교수지만 해당 제47조제2항의 날짜 해석을 확인하는 자료로만 썼다.
- [경기도교육청 2025 인사실무편람 p.73](https://www.goe.go.kr/resource/old/BBSMSTR_000000000144/BBS_202503240827049250.pdf)의 법령 설명과 교차 확인했다. 과거 편람이 2026년 법령 전문을 대체하지 않는다.
- 자동 적용은 국공립, 유치원·초·중·고·특수학교 일반 정규 교사, 사용자 제47조 적용 확인, 유효한 생년월일에 한정한다. 교육공무원법 시행일보다 앞선 정년일에는 이 버전을 자동 적용하지 않는다. 교장·교감·대학·기간제·기타·사립은 별도 임기·신분·정관 검증이 필요해 직접 입력한다. 대학 65세 규정을 확인했어도 계약·신분까지 자동 판정하지 않는다.
- 2월29일 출생자의 별도 해석례 존재는 검색에서 확인했으나 전문을 검증하지 못했다. 평년 생일을 2월28일로 임의 치환하지 않고 자동 산정을 차단한다.
- [국가법령정보센터 사립학교법](https://www.law.go.kr/lsInfoP.do?joNo=003100&lsId=000888)과 기존 조사 제4절에 따라 사립의 학교급·직위·법인 정관을 확인해야 한다. 공립 정년을 일괄 준용하지 않는다.

날짜의 '검증된 추정값'은 위 좁은 적용 범위의 현행 날짜 규칙·경계 검증을 뜻한다. 신분·미래 법령·인사발령의 확정이 아니다. 미래 시행 개정의 완전한 목록을 확보하지 않았으므로 장래 규정 변경이 없다고 보장하지 않는다.

## 명퇴 자격과 선정·지급

기존 `pension-calculation-research.md` 제4·10절의 미검증 급여 산식 차단을 유지한다. [충청북도교육청 2026년 2월말 공고](https://www.cbe.go.kr/upload/cbe/na/bbs_1762/2025/10/B8B5A36A-2425-3D01-9D6A-7196FBC836F2.pdf)는 국가공무원 규정·교육공무원 특례·사립학교법에 따른 신청과 대상자 결정을 구분한다. 해당 회차를 다른 지역·미래 회차의 선정 보장으로 사용하지 않는다.

앱은 달력상 근속연수로 자격을 자동 확정하지 않는다. 자격 확인 상태와 선정 상태는 사용자가 기관 확인 후 독립적으로 기록한다. 명퇴수당은 두 상태가 확인되고 공식 금액·조회일·가정 퇴직일·세전/세후가 유효할 때만 결과로 표시한다. 미확정 입력액은 보존하되 예상 자산 합산에는 사용하지 않는다. 선정 상태 자체도 앱이 진위를 확인한 공식 판정이 아니다.

## 데이터 재사용과 독립성

`RetirementComparisonInput`은 부모 `Planner`의 메모리 상태다. 기본 화면은 명퇴·정년 두 열, 선택 시 사용자 지정 세 번째 시나리오를 추가한다. 모바일과 좁은 화면에서는 세로 배치한다. 메뉴 이동 시 모든 입력을 유지하고 새로고침 시 초기화한다.

- 공적연금·퇴직수당은 기본적으로 02의 선택 제도별 입력을 실시간 연결한다. 조회 시 가정한 퇴직일이 시나리오와 정확히 같아야 사용한다. 사용자 추정 금액은 공식 조회값으로 승격하지 않는다. 불일치하면 새 조회를 안내한다.
- 다른 퇴직일의 공식 금액은 시나리오 내 제도별 별도 원장에 입력한다. 금액을 여러 메뉴에 반복 입력할 필요 없이 일치하는 02 원장을 재사용하고, 별도 원장은 02 값을 덮어쓰지 않는다. 퇴직일·제도 변경 시 이전 조회 조건을 자동으로 바꾸지 않는다.
- 공제회는 03의 현재 잔액·기준일·납입액·이율/변경 가정을 기존 `simulateKtcuAccumulation`에 전달한다. 상품은 장기저축 모델 범위로 제한하며 상품별 공식 금액으로 표현하지 않는다. 선택적으로 03의 현재 선택 상품의 공식 일시금 조회액을 연결할 수 있으나 해당 퇴직일·조회일·세전/세후가 필요하다. 월/연 지급액은 적립금으로 합산하지 않는다.
- IRP·연금저축은 04의 현재 잔액·기준일·연간액·주기·수익률·수수료·계좌 선택·세액공제 재투자 설정을 기존 `simulateIrp`에 전달한다. 사용자가 제외한 계좌는 합산 대상에서 제외한다. 계산된 0원과 미입력/null을 구분한다.
- 각 계좌의 기본 납입 종료는 해당 퇴직일이다. 기존 메뉴 종료일 또는 별도 종료일로 바꿀 수 있다. 퇴직 이후 종료일도 기록하지만 현재 스냅샷은 퇴직일까지 납입만 반영한다. 초기 납입액/수익률은 연결하고 선택 입력으로 시나리오별 수익률을 덮어쓸 수 있다. 공제회 변경 금리의 적용일이 퇴직 이후면 이 시점에는 미반영임을 알린다.
- 시나리오 복사본만 계산하므로 03·04의 퇴직일·종료일·수익률과 공식 원장은 변경하지 않는다. 재투자 설정은 계산 검증에 반영하되 일반 계좌 재투자 자산·환급 현금은 연금자산 합산에서 제외한다. 금액 이전 가능성을 새로 확정하지 않고 이전 입력도 다시 더하지 않는다.

## 합산·그래프·기간의 한계

합산 대상은 세전 퇴직수당, 선정 확인된 명퇴수당(명퇴만), 공제회, 포함된 IRP·연금저축이다. 공적연금 월액은 더하지 않는다. 금액 누락·선정 미확정·세후 조회액이 있으면 전체 합계는 null이고 확인된 세전 항목의 소계만 표시한다. 명퇴수당은 정년·사용자 지정 시나리오에서는 해당 없음으로 설명한다.

모델은 부분 월을 제외한다. 따라서 실제 최종 계산월이 퇴직일과 다르거나 공제회/연금계좌의 현재 잔액 기준일이 다르면, 같은 시점의 합계·소계 및 구성 막대를 생성하지 않고 항목별 금액·계산일·조정 사유만 표시한다. 안전 정수 범위를 넘는 합계도 보류한다. 날짜가 서로 다른 명퇴·정년 자산에는 차액·승자·수익률 우위를 표시하지 않는다.

자산 구성 그래프는 각자의 퇴직일과 공식 조회/가정 값을 표시한 스냅샷이며 같은 날짜의 순자산 비교가 아니다. 공적연금 미지급 기간은 퇴직일부터 확인된 지급개시일까지 달력 월·나머지 일·전체 일수를 표시한다. 일수 기준 막대는 동일 눈금을 쓴다. 이것은 다른 소득이 전혀 없다는 뜻이나 생활비 부족액이 아니다. 개시일·조회 조건이 불명확하면 기간도 계산 불가다. 최초 임용일로 연금개시일을 임의 생성하지 않는다.

동일 기준연령 비교, 연금 인출·생활비·재취업 소득·물가·퇴직 후 자산 경로·최종 유불리는 **은퇴 현금흐름 단계에서 제공 예정**이다. 기존 신뢰도와 참고용 안내문을 유지한다.

## 모듈과 테스트

`retirement-comparison-input.ts`: 비교 입력 계약/빈 초깃값. `retirement-comparison-validation.ts`: 제한된 정년 산정, 날짜 및 개시 전 기간. `retirement-comparison.ts`: 공식 조회 조건 확인, 기존 엔진 어댑터, 합산 차단. `retirement-comparison-panel.tsx`: 입력·결과·그래프. 새로운 급여 산식은 구현하지 않았다.

단위 테스트는 정년 학기 경계·윤년 말일·자동 지원 밖 신분·명퇴일 역전/동일·조회일 불일치·미입력·선정 미확정·종료일 변경·제도별 원장·중복 합산·기준일 불일치·입력 불변성을 확인한다. 정년 규칙 외 합성 금액은 어댑터 동작·합산 테스트용이며 법정 급여 계산 정답 검증 사례가 아니다.

검사 결과(2026-11-07): 단위 테스트 99/99(신규 비교 15개), 전체 데스크톱·모바일 브라우저 36/36, 타입 검사 및 프로덕션 빌드 통과. 새 브라우저 검사는 공식 조회 조건·동일/역전 날짜·선정 미확정·입력 유지·기존 데이터 재사용·종료일 수정·원본 보존·모바일 세로 배치/가로 넘침을 확인한다. 초기 실행에서 선택 항목의 접근성 레이블과 중복 버튼/알림 탐색을 수정했고, 첫 입력 누락을 피하도록 공적연금·비교 테스트 준비 시 메뉴 상호작용을 먼저 확인했다. 임의 대기나 실패 무시로 통과시키지 않는다. 기존 공적연금·공제회·IRP 회귀 검사도 포함했다.

다음 우선순위는 원천별 현금흐름 계약과 지급 시점·생활비·세금의 구분 설계다. 이후 동일 연령 비교와 명퇴 자격/법인 정관 확인을 확대한다. 이번 단계에서 자동 진행하지 않는다.
