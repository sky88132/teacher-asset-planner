# 공무원연금 월액 미표시 디버깅

기준일: 2026-11-09. 시작 브랜치 `main`, 시작 커밋 `0749242`. 기존 생성 파일 변경과 로그3개를 보존했다. 코드 수정·로컬 검증만 진행하며 커밋·Push·배포는 하지 않는다.

## 1. 실제 입력 범주에서 확인한 원인

사용자가 추가로 알려준 비식별 범주는 **현재1~39호봉, 퇴직 시40호봉, 2010년 이후 임용, 군복무 산입 승인**이다. 정확한 생년월일·임용일·계좌 등은 받지 않았으며 테스트에 복사하지 않았다.

군 산입 승인만으로 표준 모델 전체를 차단하는 조건을 확인했다. 수정 전 `estimateTeacherPension()`에는 다음 조건이 있었다.

```ts
if (p.military === 'approved') errors.push(/* 군 산입 인정개월·연도 확인 필요 */);
const rows = eligible && !errors.length && /* 소득·기간 */ ? /* 기존 연금 계산 */ : [];
```

따라서 보수 경로·평균소득·전체 평균이 생성되어도 군 승인 플래그가 있으면 재분배·연금 시나리오 생성 단계에 도달하지 못했다. 최종 선택은 비어 있는 공단 확인 소득 경로로 되돌아가 `null`을 반환했다. 05가 존재하는 계산값을 숨긴 문제가 아니었다.

**퇴직 시40호봉 자체는 차단 조건이 아니다.** 현재40호봉은 과거 어느 시점에 상한에 도달했는지 유일하게 역산할 수 없어 별도 보류한다. 두 경우를 구별한다. 알려진 군 승인 조건은 확정적인 차단 원인이지만, 사용자의 정확한 입력을 수집하지 않았으므로 다른 차단 조건이 함께 있는지까지 확인했다고 주장하지 않는다.

## 2. 이전 성공 테스트와 달랐던 점

이전409만원 사례 A는 2017년 임용·현재20호봉·명퇴·군 미산입인 가상 사례였다. 당시 군 승인 경력은 금액 보류를 정상으로 기대하는 테스트로 관리되어 있었다. A의 성공은 군 승인 입력에서도 금액이 표시된다는 검증이 아니었다.

이번에는 별도 가상 B를 만들었다. 2016년 임용·현재24호봉·정년·미래40호봉·군 산입 승인의 범주만 재현했다. 생년월일·임용 월일 등 구체적인 값은 임의 가상 자료다. 별도 C는 소득을 입력하지 않고 상세 확인/소득 방식만 변경한 상태를 검증한다.

## 4. 최소 수정과 계산 범위

### 군 산입 승인 경로

`teacher-pension.ts`에서 공식 확인 소득 경로와 **임용 후 재직분만 계산하는 참고 경로**를 분리했다. 참고 경로는 기존 `estimateCivilPension()`을 다시 사용한다. 법정 연금 산식, 지급률, 재분배 구간, 이행률 표, 봉급표·연3% 가정, 호봉 승급 함수는 바꾸지 않았다.

- 실제 입력의 `military: 'approved'`는 그대로 보존한다.
- 별도 계산용 복사본에서 군 산입분을 제외한다. 개인의 실제 인정기간이0개월이라고 판정한 것이 아니다.
- 평균·이행률·인정기간·상한 모두 같은 제외 범위를 사용한다. 군 개월만 일부 추가하고 소득·이행률을 다르게 처리하지 않는다.
- 공단 확인 소득을 실제 입력한 경로와 유효한 공식 월액 조회 입력은 종전 우선순위를 유지한다. 해당 경로의 군 인정개월·산입연도 검증을 제거하지 않는다.
- 참고액에는 `MILITARY_CREDIT_EXCLUDED` 제한 코드를 부여한다. 제목·신뢰도·설명·종합 월액 항목·AI 요청문에 **군 산입분 제외, 전체 예상액 아님**을 표시한다.
- 이 금액은 실제 전체액의 하한·최소 보장액도 아니다. 군 산입은 기간뿐 아니라 적용비율·상한·소득에도 영향을 줄 수 있어 임의로 덧셈하지 않는다.

### 빈 확인 설정 경로

이전 `hasIncome` 판정은 소득뿐 아니라 확인 날짜나 소득 방식 선택만으로도 참이 되어 참고 경로를 중단했다. `pension-income.ts`의 `hasEnteredPensionIncome()`에서 실제 소득·계수의 비어 있지 않은 입력만 판정한다. 자동 경로에는 생성된 평균소득 방식을 명시하여 빈 '현재 소득' 선택이 생성된 평균소득을 무효화하지 않도록 했다. 실제0·문자·일부 수동 소득은 계속 검증 오류로 처리하며 자동값으로 덮어쓰지 않는다.

## 5. 오류 코드와 사용자 설명

개인정보 로그나 입력 스냅샷을 수집하지 않는다. 계산 결과 객체의 코드와 문구만 사용한다.

| 코드 | 의미 |
|---|---|
| `PAY_MODEL_UNAVAILABLE` | 기본정보·보수 모델의 적용 조건 확인 필요 |
| `PAY_HISTORY_UNRECONSTRUCTABLE` | 현재40호봉·과거 역산 범위 등으로 이력 재구성 불가 |
| `PRE_2010_INCOME_REQUIRED` | 구기간 소득·경과 자료 필요 |
| `COMPLEX_CAREER_UNSUPPORTED` | 중단·휴직·시간제·재임용 등 미지원 |
| `PENSION_TIMING_OR_SERVICE_UNAVAILABLE` | 정상 개시 조건·10년 인정기간 등 확인 필요 |
| `WHOLE_INCOME_ASSUMPTION_UNAVAILABLE` | 전체 평균의 자료 범위·물가 가정 문제 |
| `CONFIRMED_INCOME_OR_CONTEXT_REQUIRED` | 선택된 공단 확인 소득 경로의 입력 미완료 |
| `QUOTE_VALIDATION_FAILED` | 직접 월액 조회 입력의 유효성 확인 필요 |
| `MILITARY_CREDIT_EXCLUDED` | 실패가 아닌 참고액의 범위 제한: 군 산입분 제외 |

05는 월액이 없으면 실제 모델의 차단 이유를 기본 요약 바로 아래에 표시한다. 빈 공단 소득만 요구하던 우회 경로의 오류를 실제 이유처럼 보여주지 않는다. 정상 개시일은 월액과 별도로 유지한다. 06도 같은 이유와 제한 범위를 보존한다.

## 6. 입력 저장·화면 연결 확인

- `SimplePlanner`는 React 상태와 `useMemo([input,today])`로 동일 계산 결과를05에 전달한다. 메뉴 변경 시 입력이 유지된다.
- 브라우저 저장소·DB·서버 저장·이전 입력 JSON 복원 경로는 없다. 저장된 옛 구조가 원인이라는 근거는 찾지 못했다.
- `calculateSimple`의 `pension`과 `pensionDetails`,05의 월액,06의 재계산 결과가 같은 금액인지 검사한다. 참고값이 있는데 표시 조건만 숨기는 문제는 발견하지 않았다.
- 사용자 입력·생년월일·임용일을 런타임 로그에 출력하지 않는다. 가상 테스트 이외의 개인정보를 이용하지 않았다.

## 7. 실제 브라우저 검증

- 수정 전 A/C: 기존 빌드의 PC·모바일에서 A 성공, 빈 설정 C 미표시·AI 미반영을 확인했다(4개 실행 통과, 진단 UI 전용2개는 의도적으로 미실행).
- 군 범주 확인 후 A/B: 군 승인 차단이 남아 있는 빌드에서 A 성공·B 월액 미확인·AI 미반영을 PC·모바일로 재현했다(4개 실행 통과).
- 수정 후 A/B/C와 현재40호봉 보류: PC·모바일8개 통과. B의 월액·제외 안내·호봉 변경 후 갱신·06 반영을 확인했다. B 모바일은320px 가로 넘침도 확인했다.
- 과거40호봉 이력 부족에서는 여전히 금액을 보류하되 실제 이유·정상 개시일·AI 설명이 유지되는지 확인했다.

## 8. 테스트 및 미지원 범위

- TypeScript: 통과.
- 단위·금융 경계: 기존458개+신규10개, 총468개 통과·실패0. 기존100명 가상 사례 포함.
- 최종 프로덕션 빌드: 동일 버전 로컬 WASM·Webpack 경로 통과. 이전 설치에서 검증용 WASM 패키지가 없어 초기 시도가 실패했으며 `--no-save --package-lock=false`로 복원했다. `package.json`·lockfile은 바꾸지 않았다. 표준 네이티브 빌드의 기존 Windows 실행 제약은 해결하지 않았다.
- 전체 E2E 회귀: 최종 빌드에서168개 통과·실패0·미실행0(PC84·모바일84). A/B/C와 보류 사례8개도 포함한다. 기존 기능·메뉴 이동·입력 유지·모바일·AI 복사·미전송 검사를 함께 실행했다.
- 실제 사용자 전체 프로필·실제 공단 전체 지급액·실기기 Safari 대조는 미실행이다. 이번 통과가 군 산입 포함 실제 전체액 검증 완료를 뜻하지 않는다.

여전히 전체 자동 월액을 제공하지 못하는 조건: 구기간 소득·경과자료가 없는2009년 이전 재직, 현재40호봉 등 과거 이력 역산 불가, 복잡 경력, 자료 범위 밖 전체 평균 가정, 유효하지 않은 수동 소득·조회액 등. 군 산입 포함 전체액에는 인정 개월·연도·소득·경과규정이 필요하며 이번에는 임용 후 경력 참고액만 제공한다.
