# 7단계 은퇴설계 종합 분석·맞춤형 조언

작업 기준일: **2026-11-08, Asia/Seoul**. 사용자 요청에 따라 중단 시점의 변경사항을 보존하고 이어서 구현했다. 1~6단계 계산을 재사용하며 외부 AI API·계정·DB·배포·커밋·Push를 추가하지 않는다. 8단계는 진행하지 않는다.

## 1. 재개 시점 점검과 이어서 한 작업

Git 기준 커밋은 6단계 `4c26743`이었다. 재개 때 이미 수정되어 있던 파일은 `model.ts`의 선택 생활비 필드, `overview.tsx`의 분석 컴포넌트 연결, `planner-theme.css`의 분석 스타일이었다. 신규 미추적 파일 `retirement-analysis.ts`, `retirement-advice.ts`, `retirement-strategy.tsx`에도 분석·조언·화면이 작성되어 있었다. 이 코드를 초기화하거나 중복 구현하지 않았다.

기존 [고도화 계획](retirement-calculation-upgrade.md), [5단계 공적연금 기록](public-pension-estimation.md), [6단계 수령 조건 기록](account-receipt-conditions.md)과 실제 모듈을 확인했다. 빠진 AI 요청문 연결·전용 테스트·완료 기록을 추가하고, 검토에서 발견한 표현·익명화·잔액 기준 문제를 보완했다.

5단계는 지원 경력에서 조건부 공적연금 금액/시점을 제공한다. 필수 소득·계수가 없으면 금액은 null이고 개인별 외부 금액 검증 미완료다. 6단계는 계좌별 가입일·55세·5년·실제 이연퇴직소득 예외와 독립 한도를 제공하며 월 인출 일정과 세후액을 만들지 않는다. 이번 단계도 이 제한을 그대로 유지한다.

## 3. 소득 공백과 타임라인

예상 퇴직일·퇴직 당시 만 나이, 정상 공적연금 조건 충족일, **실제 분석에 적용한 개시 기준**, 기존 공백 개월·일수, 월연금·금융 적립금·퇴직급여를 요약한다. 공무원·사학·국민연금의 기존 결과 또는 유효한 직접 조회값을 재사용하며 65세를 일괄 적용하지 않는다.

A는 퇴직 후 공적연금 개시 전, B는 개시 후다. 퇴직일과 개시일이 같거나 이미 개시됐으면 공백은 0이며 A의 비교 구간이 없다고 설명한다. 과거 개시일을 향해 역방향 공백 화살표를 그리지 않는다. 날짜 미확인은 공백 0과 구분한다.

자동 공적연금은 최초 지급대상월 1일이 분석 기준이고 실제 현금 입금일이 아니다. 직접 조회값은 입력한 개시일이 기준이다. 정상 조건 충족일은 별도 표시하여 혼동을 줄인다. 명퇴는 공백 재원·시점을 우선 조언한다.

## 4. 자산 용도와 공제회 활용

| 구분 | 포함 | 제외·한계 |
| --- | --- | --- |
| A. 일시 수령 검토 재원 | 일시금 선택 공제회, 계산 가능한 퇴직수당·명퇴수당 | 지급·선정·세금·입금 미확정. 하나라도 누락이면 전체 합계 미표시. 연금계좌와 월연금 제외 |
| B. 기간 분할 재원 | 분할 선택 공제회 기존 지급표 | 일시금 항목에서 공제회 제외. 기존 지원 기간·최종 정산·차감 후 잔액 재사용 |
| C. 조건부 연금계좌 | IRP·연금저축의 퇴직 적립금과 6단계 요건·한도 | 55세만으로 즉시 쓸 목돈에 합산하지 않음. 미충족/가입기간 미확인 구분 |

공제회는 5·10·15·20·25·30년 선택을 유지한다. 공백 길이에 맞춰 7년 등 임의 상품 기간을 만들지 않는다. 기존 가상 지급표에서 첫 지급일·마지막 지급일·정기 월액·마지막 정산액과 개시 전후 지급 횟수를 가져온다. 선택한 기간이 공백보다 짧으면 종료 후 이 월액은 사라지고, 길면 개시 후에도 계속되는 지급 횟수를 보여준다.

누적 지급액과 남은 잔액은 기존 지급표의 `paymentWon`·`balanceWon`을 사용한다. 잔액 비교 기준은 **퇴직일과 공적연금 개시일 중 늦은 날 직전**이다. 그 날짜 전에 지급된 행만 누적하며, 지급액을 원래 적립금과 다시 합산하지 않는다. 잔액이 소진된 뒤에는 0을 표시한다. 이 값은 실제 계좌 조회 잔액이 아닌 가상 일정의 잔액이다.

현재 세전 공제회 잔액 전체를 가상 분할 원금으로 사용한다는 1~6단계 한계를 유지한다. 실제 전환 가능 세후액·가입 자격·최소 금액·지급 조건은 확인이 필요하다. 일시 재원 합계도 공제회 수익률 가정과 2026년 가격 고정 수당을 결합한 참고 시나리오이며 같은 확정 실수령 현금으로 취급하지 않는다.

## 5. IRP·연금저축과 수당 조언

IRP와 연금저축은 계좌별 요건 충족 예상일·퇴직일 충족 여부·공백 활용 검토 가능 여부·한도를 6단계에서 가져온다. 상세 설정은 03에 그대로 둔다. 요건을 충족해도 실제 신청·한도·재원·세금·잔액 제한이 남는다.

6단계의 연간 한도 산입 인출 입력은 수령한도 검토용으로, 이를 12로 나눠 월소득으로 간주하지 않는다. 이번에는 개인 계좌 인출을 실행하거나 월 지급을 새로 설계하지 않는다. 퇴직 적립금은 **퇴직 시점 스냅샷**으로만 표시하고 인출 후의 미래 잔액으로 재사용하지 않는다. 이후 인출을 설계할 때 반드시 지급액을 잔액에서 차감해야 함을 명시한다. `accountWithdrawalSchedule=null`을 유지한다.

명퇴수당·퇴직수당은 기존 신뢰도·세전 기준을 유지하고 계산 불가면 확정 자금으로 사용하지 않는 조언을 생성한다. 일반적인 용도로 공백 생활비·비상예비자금·예금 등 안정적 자산과 투자자산의 역할·유동성·일괄 투자 위험·장기 투자자산의 급매 방지를 다룬다. 생활비·위험 성향이 없어 특정 상품·비율을 추천하지 않고 수익을 보장하지 않는다.

## 6. 선택 생활비와 월수입 그래프

추가 입력은 **은퇴 후 희망 월 생활비(만원)** 하나다. 내부는 원 단위이며 소수 넷째 자리까지 유지한다. 비어 있으면 null이고 0원 생활비를 가정하지 않는다. 일반 조언과 기존 화면은 계속 작동한다.

공적연금·공제회 중 계산 가능한 월액만 그래프에 사용한다. 전후 두 구간 안에서 다음 경계를 나눈다.

1. 퇴직 후 공제회 첫 지급 전.
2. 공제회 정기 분할 지급 중.
3. 공제회 마지막 지급일의 잔액 정산.
4. 공제회 분할 종료 후.
5. 위 구간 사이 공적연금이 개시되면 그 날짜에서 추가 분리.

각 막대는 해당 구간의 **월 지급액 수준 예시**다. 구간 전체 평균·일별 실제 현금흐름이 아니다. 월연금과 일시금은 한 그래프에서 합산하지 않는다. 마지막 정산액은 정기 월액과 별도다. 분할 종료 이후를 같은 월액으로 연장하지 않는다.

근로·임대·기타수입과 IRP·연금저축 월 인출은 **미반영**이다. 확인된 항목이 없으면 월액을 null로 두고 막대를 그리지 않는다. 공제회만 계산 가능하면 부분소계와 누락 공적연금 표시를 함께 보여준다. 세후 조회월액과 세전 분할월액처럼 세금 기준이 다르면 합계와 차이를 보류한다. 명시적으로 계산된 0원은 미확인과 구분한다.

생활비를 입력하면 `계산 가능한 월액 소계 − 희망 월 생활비`를 계산한다. 결과 이름은 **생활비 대비 선택 자료 차이**이며 정확한 부족액·잉여액이나 세후 생활비 충당액이 아니다. 세전 소계는 세전임을 표시한다. 미확인 수입을 0원으로 채우거나 총자산을 기간 개월로 나누어 인출 가능액으로 표시하지 않는다.

## 8. 06 AI 요청문 연결

기존 구조에 `6-2. 은퇴설계 종합 분석` 데이터 블록만 추가했다. 생활비·공백·일시 재원·공제회 지급 일정/잔액·월액 구간·계산 가능한 차이·미반영 수입 및 규칙 기반 조언의 4요소를 포함한다.

화면과 같은 분석·조언 함수를 사용하되, 금액 포맷을 기존 요청문의 정확/반올림/구간 설정으로 주입한다. 조언 안 날짜도 기존 날짜 익명화 함수를 거친다. 원래 개인정보 검사·복사 차단을 완화하지 않았다. 요청문 생성기 전면 개선인 8단계는 시작하지 않았다.

## 9. 근거와 검증 한계

이 단계는 새 법정 급여 산식을 만들지 않았다. [5단계 공식 근거](public-pension-estimation.md)와 [6단계 공식 세법](account-receipt-conditions.md)을 따른다. 2026-11-08에 [공제회 분할급여 안내](https://www.ktcu.or.kr/PPW-FIA-300100), [국세청 연금소득 안내](https://nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7888&mi=6608)를 다시 확인했다. 공제회 실제 기간·상품 조건과 세원별 과세를 새 조언에서 임의 완화하지 않았다.

개인별 공적연금·수당의 실제 금액, 실제 공제회 전환액/분할 지급액, 계좌 세후액·공제 이력·실제 인출 가능액, 다른 소득·생활비 전체 현금흐름·물가·시장수익률은 미검증/미반영이다. 화면·요청문에 이 한계를 유지한다.

## 11. 완료 범위와 다음 단계

7단계는 지원 범위 내 분석·규칙 기반 조언과 05/06 연결을 제공한다. 인출을 실행하거나 확정 세후 재무계획을 만드는 기능은 아니다. 공식 자료·개인별 지급액의 기존 한계는 남아 있다. 8단계 진행은 가능하나 별도 지시 전 시작하지 않는다. Production 설정·배포에 영향을 주지 않는다.
