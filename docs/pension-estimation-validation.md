## 1. 공식 산식과 구현 경계

공무원연금은 2009년 이전, 2010~2015년, 2016년 이후를 나눈 기존 `occupational-pension.ts`를 재사용한다. 해당 구간마다 인정 월수/12로 연수를 적용한다.

- 구기간은 재평가된 평균보수월액과 종전 지급 구조를 사용하며, 실제 소득·경과규정이 부족하면 전체 금액을 보류한다.
- 2010~2015년은 개인 평균기준소득월액 B × 재직기간별 적용비율 k × 연수 × 1.9%다.
- 2016년 이후는 재분배된 소득 × k × 1% 부분과 B × k × (연도 지급률−1%) 부분을 구분한다. 총 재직기간 30년 초과분은 재분배 대상에서 제외하며, 종전 산식 비교 상한과 연금 재직기간 상한도 별도로 적용한다.
- 퇴직수당 인정기간 상한은 396개월(33년)이다. 연금의 33~36년 경과 상한과 혼용하지 않는다.

이는 모든 예외를 완성한 공단 확정 산식이라는 뜻이 아니다. 개인별 과거 소득, 직종별 수당 평균, 재평가계수, 이행률, 병역·합산 경력과 각종 감액·경과규정은 별도 확인 대상이다. 사학·국민연금에는 공무원 교원 보수 모델을 자동 적용하지 않는다.

## 3. 자동 산출 변수

기본정보 → 월별 재직기간 → 승급월별 호봉 → 연도별 봉급·수당 → 소득 대용치 → 개인 평균 B → 별도 전체 평균 A → 재분배 B/A 구간 → 이행률 → 기간별 월연금 → 05·06 순으로 연결한다.

- 2026 봉급표의 연3% 인상과 호봉 승급은 별개로 한 번씩 적용한다.
- 현재보다 과거 호봉은 조건부 역산하며, 40호봉 등 이력이 유일하게 정해지지 않으면 보류한다.
- 전체 평균 A는 퇴직 전 3개 연도 각각의 전체 평균을 산출하고, 각 연도에서 퇴직 전년도까지의 물가 가정을 반영한 뒤 평균한다. 직전 한 해의 소득을 그대로 사용하지 않는다.
- 미래 전체 평균은 2026 고시 595만원 × 1.03^(연도−2026)이다. 개인 교원 소득 B와 같게 강제하지 않는다.
- 3개년 평균을 전년도 가격의 대용치로 보고 개시연도까지 미래 보수 인상 가정으로 환산한다. 이후 B와 동일한 기준으로 B/A를 비교한다. 5월 적용과 개인 소득의 정밀 환산은 별도 미검증 범위다.
- 재분배 비율은 기존 법정 구간표를 사용한다. 신규자 이행률도 기존 기간별 표를 사용하며 100%로 고정하지 않는다.
- 정상 개시 조건 충족일과 최초 지급대상월은 월액 계산과 별개로 표시한다. 소득이 부족해도 시기를 확인할 수 있으면 숨기지 않는다. 조기연금은 자동 선택하지 않는다.

## 5. 가정과 미구현 범위

- 담임20만원과 교직25만원 등 고정 수당에 봉급표 연3%를 자동 적용하지 않는다. 기존 정근·명절 봉급 연동 부분만 봉급에 따라 변한다. 특수·보직·가족 등 개인 조건 수당을 모든 교원에게 추가하지 않는다.
- 실제 과거 봉급표 전체, 과거 실제 소득과 법정 재평가계수, 직종별 평균 8개 수당은 이번에 확보하지 못했다. 기존 2026 표 기준 대체 경로를 **실제 과거 소득·법정 평균 산정 완료로 표현하지 않는다**.
- 과거 물가 환산이 필요한 2028년 이전 퇴직은 새 전체 평균 자동 경로에서 보류한다. 기본정보 자동 월액을 가능하게 하려고 실제 과거 물가를 임의 생성하지 않는다. 공식 조회액·공단 확인 소득 경로는 유지한다.
- 미래 물가0%는 보수 인상3%와 다른 가정이다. 물가 고정 비교와 실제 구매력을 구별한다. 입력 지원 범위 0~20%는 법정·통계 예측 범위가 아니다.
- 90/100/110%는 기존 소득 민감도이며 실제 지급액 최소·최대 또는 오차율이 아니다. 구간 재분배 때문에 월액 순서·차이가 단순 비례하지 않을 수 있다.

구간 판정은 표시용2026 환산 A가 아니라 개시연도 원 단위 B/A로 수행한다. 재분배 소득도 해당 개시연도 B에 법정 비율을 곱한 후 원 미만 절사한다. 중간2026 금액을 절사한 뒤 다시 증액하면서 생기는 이중 절사와, 서로 다른 가격 기준의 비교를 피한다. 미래 명목 결과에 남아 있던2026 고정 입력 경로의 안내도 제거했다.

기준 퇴직수당83,998,123원 + 미래 명목 명퇴수당228,559,838원 =312,557,961원이다. 원 단위로 합산한 뒤 만원 표시하며 반올림한 카드 표시액끼리 재합산하지 않는다.

`selectBenefitSummary()`가 하나의 선택 결과를 만든다. 미래 교원 보수 경로가 가능하면 그 기준 결과를 우선하고, 불가능하면 기존 소득 수준 고정 경로와 미확인 상태를 명시한다. 04·05·06과 종합 분석의 일시금 항목이 같은 결과를 사용한다. 미래 금액과2026 고정 금액을 혼합하지 않는다. 통계 소득 기반 고정 시나리오는 상세 비교에 남겨 기존 입력·기능을 보존한다.

퇴직수당 증식 산식은 기존 `allowanceAmount()`를 공유한다. 2010년 이후 직접 소득 경로에서 참고 계산이 같은 산식을 다시 계산하던 부분은 `estimateAllowance()` 결과를 재사용하게 했다. 구기간은 별도 경과 구조를 유지한다. 월연금은 퇴직금·적립금 합계에 더하지 않는다.

04는 명퇴 시 명퇴수당→퇴직수당→참고 합계 순서로 표시하며 주요 금액은 접지 않는다. 정년은 명퇴 카드를 표시하지 않는다. 이미 같은 기준 합계가 있는데 옛 '완전한 합계 확인 불가' 영역을 중복 표시하던 부분을 제거했다.

## 7. 실제 공단 예상액과 다른 이유·공식 예시 검증

실제 공단 조회액과 대응되는 개인 소득·경력 자료는 없다. 따라서 월연금 전체액과 퇴직급여 전체액의 외부 금액 검증은 미완료다. 실제 지급액 일치 확률을 계산하지 않는다.

인사혁신처의 재분배 숫자 예시는 직접 대조했다. A400만원·B600만원이면 구간 비율83.33%와 반영 소득4,999,800원, A400만원·B200만원이면150%와3,000,000원이다. 이 부분의 산술 일치는 **전체 월연금 검증 완료가 아니다**.

## 8. 완료·미완료

완료: 기존 산식 재사용, 3개년 전체 평균의 미래 가정 경로, 변수별 출처 상태, 기존 재분배·신규자 이행률 활용, 04·05·06 공통 선택 결과, 명퇴/정년 카드 정리, 보류 사유·정상 개시일 노출, 만원 표시/원 계산 유지.

미완료: 구기간 및 복잡 경력의 완전 자동 월액, 과거 봉급표·공식 과거 재평가 전수 자료, 실제 과거 CPI가 필요한 근시점 퇴직의 자동 경로, 실제 공단 전체액 대조, 개인별 세후 지급액·선정 여부. 이를 임의 입력으로 완료 처리하지 않았다.

- 타입 검사: 통과.
- 단위 테스트: 기존435개와 신규23개, 총458개 통과·실패0. 기존100명 가상 사례 포함.

- ESLint는 기존 설정이 없어 미실행. 실제 공단 금액 외부 대조와 실기기 Safari는 미실행.
- 변경·추가 코드와 보고서의 비밀키·토큰·직접 식별정보 패턴 검사: 탐지0건. 테스트 데이터는 가상 자료만 사용했다. 패턴 검사가 모든 형태의 민감정보 부재를 보증하는 것은 아니다.

## 10. 자동 월연금이 중단되는 정확한 조건

1. 기본정보 또는 퇴직일이 잘못되었거나 자동 모델 가정을 해제한 경우.
2. 사학·국민연금처럼 공무원 교원 보수 자동 모델 적용 대상이 아닌 경우. 해당 제도 확인 소득 경로는 별도다.
3. 2009년 이전 재직분의 평균보수·이행률·경과 자료가 없는 경우.
4. 현재40호봉 또는 역산한 과거 호봉이1호봉 미만 등 과거 경로를 특정할 수 없는 경우.
5. 휴직·중단·시간제·재임용 등 경력으로 표준 연속 경력을 적용할 수 없는 경우. 후속 디버깅에서는 군 산입 승인 자체로 모든 참고액을 차단하던 경로를 분리했다. 지원 경력은 군 산입분을 제외한 임용 후 재직분 참고액만 표시하며 전체액·하한이 아님을 명시한다.
6. 정상 연금 개시 조건이나10년 이상 인정기간을 확인할 수 없는 경우.
7. 미래 전체 평균3개년 경로의 자료 범위 밖(2029년 이전 퇴직) 또는 물가 입력 오류인 경우.
8. 사용자가 공단 확인 소득 경로를 선택했으나 소득·재분배·이행률·날짜 확인이 부족하거나 오래된 경우. 이를 표준 자동값으로 조용히 덮어쓰지 않는다.
9. 직접 월연금 조회액을 입력했으나 가정 퇴직일·조회일·세금·개시일이 유효하지 않은 경우. 공식 조회 경로의 실패를 자체 추정 성공처럼 바꾸지 않는다.

조건에 따라 월액은 `null`과 구체적 사유로 남긴다. 이를0원으로 대체하지 않으며 계산 가능한 정상 개시일·기간은 유지한다. 남은 공식 자료 검증과 표준 빌드 확인 전에는 전 사례의 법적 계산 완성 또는 무조건적인 공개 준비 완료라고 판정하지 않는다.

## 12. 후속 GitHub 저장 전 재확인 (2026-11-09)

후속 사용자 지시에 따라 기존 구현을 다시 만들지 않고 타입·단위·빌드·실제 브라우저를 재검증한다. 시작 브랜치가 `main`이므로 변경을 보존한 채 `fix/public-pension-integration`으로 분리했다. 저장은 이 작업 브랜치에만 진행하며 `main` 병합·강제 Push·Vercel 직접 배포는 하지 않는다.

- 타입 검사와 단위·금융 경계 테스트458개 재실행 통과.
- 기본 빌드는 동일한 Windows 네이티브 SWC 실행 정책으로 실패했다. 명시적 WASM·Webpack 경로의 프로덕션 빌드는 재실행 통과했다. 이는 기본 빌드 명령의 성공을 뜻하지 않는다.
- PC·모바일 전체 브라우저160개 재실행 통과·실패0(PC80·모바일80). 지원 가상 사례의 월연금, 세 소득 시나리오, 정년·명퇴 카드, 04·05·06 금액 일치, 퇴직일·호봉 변경, 미래 명목/2026 고정 비교를 확인했다.
- 저장 후보22개 파일의 비밀키·토큰·직접 식별정보 패턴 검사에서 실제 민감정보는 발견하지 않았다. 기존 개인정보 차단 테스트 파일1개가 `example.test` 가상 이메일 패턴과 일치했으며, 기존 커밋에도 같은 주소3회가 들어 있는 테스트 자료임을 확인했다. 실제 개인 이메일이 아니다.

- 커밋 메시지: `fix: integrate public pension estimates and retirement benefit calculations`.
- Vercel 프로젝트의 Preview·Production 설정은 연결 도구나 로컬 설정으로 직접 확인할 수 없어, Preview 배포 성공을 추정하지 않는다. 작업 브랜치 Push에 따른 자동 체크는 별도로 확인한다.
