# 교사 은퇴 연금 시뮬레이터

## 1차 서비스 범위

기존 프로젝트의 디자인과 금융 모듈을 유지하며 교사 전용 은퇴 연금 시뮬레이터로 범위를 한정합니다.

1. 교사 기본정보
2. 공적연금·퇴직수당
3. 교직원공제회
4. IRP·연금저축
5. 명퇴·정년 비교
6. 은퇴 현금흐름
7. AI 분석 요청문

개인연금, 개인 부동산, 예금·적금, 일반 주식·ETF 계좌, ISA, 대출·기타 부채와 종합 순자산 계산은 1차 서비스에서 제외합니다. 기존 개인연금·기타 자산·부채 메뉴는 준비 화면만 있었으며 메뉴 연결만 제거했습니다. 공통 모듈과 기존 입력 데이터는 삭제하지 않습니다.

명예퇴직수당은 퇴직수당과 구분하며 아직 자동 계산을 제공하지 않습니다. 명퇴·정년 비교와 은퇴 현금흐름은 공식 조회값·기존 적립/인출 모델을 연결한 조건부 시뮬레이션입니다. AI 분석 요청문은 현재 입력과 결과를 로컬 문자열로 변환하며, 정밀 연금 계산은 준비 중입니다. 대시보드의 별도 합산 요약은 미연결 상태를 명시합니다. 공적연금 월액을 적립금에 더하거나 퇴직수당과 IRP 이전금을 중복 합산하지 않습니다.

## AI 은퇴설계 분석 요청문

`07 AI 분석 요청문`은 8개 분석 목적, 간단/상세 모드, 포함 정보 미리보기, 생성·편집·전체 복사와 실패 시 수동 선택을 제공합니다. 기존 입력과 계산 결과만 사용하며 유료 AI API·자동 전송·서버 저장은 없습니다. ChatGPT·Gemini·Claude는 사용자가 공식 사이트를 직접 열어 붙여넣습니다.

기본 익명화는 날짜를 연령대·상대 시점으로 바꾸며 금액은 10만 원 단위 반올림합니다. 정확한 날짜는 익명화 OFF와 별도 동의가 모두 필요합니다. 기존 자유 메모·이름·학교명·계좌번호는 자동 추출하지 않습니다. 추가 질문은 직접 검토 후 포함하고, 식별정보 의심 줄 및 편집본을 점검합니다. 자동 탐지는 완전하지 않아 최종 검토가 필요합니다. 개인정보 옵션 변경 시 편집본은 초기화하고 다른 데이터 변경 시 재생성 전 복사를 보류합니다. 자세한 정책·제한·공식 서비스 주소 확인 기록은 [요청문 생성기 설계](docs/ai-prompt-generator.md)에 있습니다.

## 은퇴 현금흐름

`06 은퇴 현금흐름`에서 명퇴·정년 각각 퇴직월부터 최종 분석 연령 도달월 말(기본 90세)까지 월별 원장과 연도·연령별 집계를 제공합니다. 02~05 데이터를 재사용하며 생활비·물가·특별 지출·수당 지급일·공제회 일시/가상 분할·계좌 인출 조건을 추가합니다. 입력은 메뉴 이동 후 유지됩니다.

계좌 인출은 잔액에서 현금으로의 이동이며 새 자산이 아닙니다. 일시 수당은 지급월 한 번만 반영합니다. 현금 부족은 별도로 표시하고 자동 추가 인출·차입·미충당 지출의 자동 상환은 하지 않습니다. 미확정 명퇴수당은 null과 부분 결과 표시로 남기며, 누락된 필수 연금액·일시금은 0원으로 채우지 않습니다. 세금은 미반영이고 선택한 세전/세후 기준이 다른 원천은 차단합니다.

같은 연령의 은퇴 이후 잔액과 미충당 지출을 보여주지만 퇴직 전 근로소득·저축·생활비가 없어 완전한 유불리 비교는 불가합니다. 가정과 부분 월 처리·한계는 [현금흐름 설계 문서](docs/cashflow-design.md)를 참조하세요.

## 명예퇴직·정년퇴직 비교

`05 명퇴·정년 비교`는 명퇴·정년과 선택적인 사용자 지정 퇴직일을 지원합니다. 국공립 일반 교사의 확인된 적용 범위만 62세·학기말 정년일을 산정하고, 사립·대학·기간제·윤일 출생 등은 기관 확인일을 입력합니다. 명퇴 자격 확인과 수당 선정은 분리합니다.

02의 공식 금액은 가정 퇴직일 일치 시만 연결하고, 다른 날짜는 시나리오별 조회값을 보관합니다. 03·04의 잔액·납입금·수익률을 재사용하며 계좌별 종료일·수익률 가정을 바꿀 수 있습니다. 미입력·미선정은 0원이 아니며 세후 금액과 부분 월·기준일이 맞지 않는 자산은 세전 동일 시점 합산에서 제외합니다. 05는 서로 다른 퇴직일의 구성·공적연금 개시 전 기간을 표시하고, 06에서 동일 연령의 조건부 잔액을 연결합니다. 최종 유불리는 단정하지 않습니다. 근거·지원 범위는 [비교 설계 문서](docs/retirement-comparison-design.md)에 있습니다.

IRP의 기존 환급액 재투자 비교는 연금 납입에 딸린 보조 가정 계산으로 유지합니다. 이는 일반 투자계좌 관리 기능이 아니며 외부 계좌의 현재 잔액·종목을 입력받지 않습니다. 계산 엔진·공제 한도·검증 차단·안내문은 유지합니다.

## IRP·연금저축 시뮬레이터

`04 IRP·연금저축`에서 계좌별 복리 적립, 월/연 납입, 수수료, 세전 가상 인출·잔여자산, 사용자 수익률 시나리오와 연도별 그래프를 제공합니다. 일반 국세 세액공제의 이론상 금액과 남은 세액을 반영한 조건부 가능액을 구분합니다. 환급액은 자동 확정하지 않으며 사용자 확인 현금 상한에 따라 일반 투자계좌 재투자와 현금 보유를 비교합니다.

IRP·연금저축 계좌로의 환급 재투자, 퇴직수당 IRP 이전, 세후 연금액은 추가 검증 전까지 비활성화합니다. 입력은 화면 메뉴 이동 시 유지되고 새로고침 시 초기화됩니다. 공식 출처·시행 시점·계산 가정·제외 범위는 [조사 문서](docs/irp-pension-research.md)에 있습니다. 기존 공적연금·공제회와 합친 전체 자산으로 중복 합산하지 않습니다.

교사의 공적연금과 은퇴 금융자산을 바탕으로 은퇴 설계를 돕는 Next.js App Router · TypeScript · Tailwind CSS 프로젝트입니다.

## 1단계 구현

- 한국어 반응형 대시보드와 메뉴
- 학교 구분, 생년월일, 최초 임용일, 특수 경력 입력
- 학교 구분에 따른 공무원연금·사학연금 표시
- 정밀 계산 모드 및 미구현 메뉴의 준비 중 안내

1단계에서는 금융 계산, 인증, 서버 저장을 구현하지 않았습니다. 현재 공제회 가정 시뮬레이션은 제공하며 공적연금·퇴직수당 자동 산정은 검증 대기 중입니다. 입력은 화면 메모리에만 유지되며 새로고침 시 초기화됩니다. 임의 예시 금융 금액은 표시하지 않습니다. 특수 경력은 자동 산정하지 않습니다.

## 2단계 공적연금 입력

- 기존 `공적연금·퇴직수당` 메뉴에서 공무원연금·사학연금별로 월연금과 공식 예상 퇴직수당을 직접 입력합니다. 교사 기본정보의 가입제도·날짜·특수 경력과 연동하며 제도별 금액은 따로 유지합니다.
- 월연금은 공식 조회값과 사용자 추정값을 구분합니다. 공식 조회값도 사용자가 직접 입력한 값이며 기관 조회·진위 검증을 수행하지 않습니다.
- 원·만 원, 세전·세후, 조회 기준일, 산정 시 가정한 퇴직일, 연금 지급개시일 및 추가 가정을 함께 표시합니다. 필수 정보가 유효해야 결과 금액이 표시되며 미입력은 0원이 아닙니다. 단위 변경은 같은 금액을 유지하고 세전·세후 변환은 하지 않습니다.
- 퇴직수당 자동 계산 준비 영역은 인정 재직기간·최종 기준소득월액·2009년 이전 재직·특수 경력을 기록합니다. 산식·예외 검증이 남아 있어 자동 계산 금액은 표시하지 않습니다. 명예퇴직수당은 별도 급여입니다.
- 메뉴·로고 이동 시 입력은 유지되고 새로고침하면 초기화됩니다. Supabase·서버·브라우저 저장소는 연결하지 않습니다. 정밀 계산 모드는 준비 중입니다.
- 데이터 타입은 `src/lib/finance/pension-input.ts`, 금액 단위·날짜·기간 검증은 `src/lib/finance/pension-input-validation.ts`, 화면은 `src/components/pension-panel.tsx`로 분리했습니다.

## 퇴직수당 자동 계산 검증 및 판정

- 공무원·사학 제도별 순수 판정 함수를 분리하고, 자동 계산용 퇴직일·계산 기준일·인정기간 출처·감액 여부·기존 수당 수령 이력을 추가했습니다. 최초 임용일과 특수 경력은 기본정보를 참조합니다. 공식 조회액과 자동 계산 입력은 별도로 유지합니다.
- 2026-11-07 재조사에서 지급비율·33년 상한을 확인했지만, 관련 부칙·급여 끝수 처리·공식 숫자 사례 대조를 완료하지 못했습니다. **현재 자동 계산 가능 범위는 없으며, 양 제도 모두 비활성화합니다.** 금액 산식을 임의로 구현하지 않았습니다.
- 판정 결과는 `amountWon: null`, `appliedMonths: null`, `appliedRate: null`로 반환합니다. 입력한 개월수·소득은 검토 정보로만 표시하며 참고 상한·지급비율을 실제로 적용했다고 표시하지 않습니다. 1년 미만도 0원으로 바꾸지 않습니다.
- 기존 월연금·공식 퇴직수당 입력은 계속 사용 가능합니다. 자동 결과에는 차단 사유·검토 법령과 시행일·계산 기준일·미반영 사항·안내문을 표시합니다. 원 미만 급여 반올림·절사는 미검증 상태이므로 실행하지 않습니다.
- 검증 기록·공식 출처·미확인 목록은 `docs/pension-calculation-research.md` 제10절에 있습니다. 테스트는 입력·차단·경계 동작을 검증하며 **법적 지급액 정답 검증을 대체하지 않습니다.**

## 교직원공제회 입력·가정 시뮬레이션

- `03 교직원공제회`에 상품별 공식 조회액, 현재 적립금, 향후 납입·금리 변경·퇴직 시 적립 전망 및 가상 분할 인출을 제공합니다. 공식 상품 급여액 자동 계산은 미검증으로 비활성화되어 있습니다.
- 장기저축급여 적립 모델은 세전 기준 잔액과 이후 납입금만 사용합니다. 현재 월 납입액은 기록용이며 기존 잔액에 이중 가산하지 않습니다. 공식 조회액은 상품·지급 단위·조회일·수령 가정일·세전/세후와 함께 별도 보관합니다.
- 공식 확인 이율을 사용하는 경우도 미래까지 같은 이율을 유지한다는 가정입니다. 사용자 가정 이율, 변경 시나리오, 가상 인출 이율을 구별합니다. 분할급여금과 퇴직생활급여의 공식 지급액으로 표현하지 않습니다.
- 가상 인출은 수령기간별 월 지급·마지막 지급·총수령 및 선택 기간 월별 일정을 표시합니다. 세후·상품별 세금/수수료 계산은 제공하지 않습니다. 누락은 0원으로 처리하지 않습니다.
- 조사·출처·수학적 산식·부분월 제외·반올림 및 공식 사례 비교 한계는 `docs/ktcu-calculation-research.md`에 기록했습니다. 상품별 가입자격은 직접 확인해야 합니다.

## 로컬 실행 (VS Code PowerShell)

```powershell

```

```powershell
npm.cmd run typecheck
npm.cmd run build
```

금융 모듈은 `src/lib/finance/`에 UI와 분리합니다. `ktcu-simulation.ts`는 공제회 검토용 자체 적립·가상 인출 함수이며 공식 상품 계산을 대체하지 않습니다. 기본정보 모델은 `src/lib/profile.ts`, 날짜 검증은 `src/lib/profile-validation.ts`에 분리되어 있습니다.

## 기본정보 입력 개선

- 날짜·학교·연금·특수 경력을 React 상태로 관리하여 메뉴 이동과 로고 클릭 시 유지합니다. 새로고침이나 새 탭에서는 초기화됩니다. 브라우저 저장소와 서버에는 저장하지 않습니다.
- 학교 구분은 연금 기본값만 제공합니다. 실제 가입 제도를 직접 선택할 수 있고, 직접 선택한 값은 학교 변경으로 덮어쓰지 않습니다.
- 군 복무·육아휴직·기타 휴직·과거 재직기간 합산은 복수 선택할 수 있습니다. 상세 경력 입력 및 계산 반영은 제공하지 않습니다. `specialCareerDetailsEntered`는 상세 기간 등의 입력 여부이며 단순 경력 선택과 구분합니다.
- 날짜는 `YYYY-MM-DD` 문자열로 검증합니다. 윤년·달력·필수 입력·미래 날짜·생년월일과 임용일의 순서를 확인하며 오늘 날짜는 `Asia/Seoul` 기준입니다. 오류는 제출 후 항목 아래 표시되고 수정 시 다시 검증됩니다.

```powershell
npm.cmd test
npm.cmd run test:browser
```

단위 테스트는 현재 환경의 Node.js 26에서 TypeScript 직접 실행 기능을 사용합니다. 브라우저 테스트는 Microsoft Edge가 설치된 Windows 환경을 기준으로 데스크톱과 모바일 크기를 검사합니다. 실제 휴대폰 검증을 대신하지는 않습니다.
