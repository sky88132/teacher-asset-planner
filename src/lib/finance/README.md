# 금융 계산 엔진

IRP·연금저축은 `irp-input.ts`(입력 계약), `irp-validation.ts`(검증), `irp-tax.ts`(일반 국세 공제·이전 차단), `irp-simulation.ts`(순수 월별 적립·인출 모델)로 나뉩니다. 음수 수익률을 지원하며 수익→수수료→후납 순서, 원 단위 반올림, 부분 월 제외를 명시합니다. 일반 계좌 환급 재투자에는 추가 공제를 적용하지 않고 비교 상대도 같은 환급금을 현금으로 보유합니다. 계좌 내 재투자·퇴직급여 이전·세후액은 지원하지 않습니다. 상세는 `docs/irp-pension-research.md`를 참조하세요.

공무원연금과 사학연금은 별도 모듈로 구현할 예정입니다. 공식 자료, 시행일, 경과규정 확인 후 계산과 단위 테스트를 함께 추가합니다. 원 단위 정수·명시적 반올림을 사용하고 세전·세후 및 명예퇴직수당·퇴직수당을 구분합니다.

현재 `pension-input.ts`는 제도별 입력 타입과 빈 초깃값, `pension-input-validation.ts`는 원·만 원의 정확한 환산 및 날짜·준비 입력 검증을 제공합니다. 급여·세금 산식은 구현하지 않습니다. 빈 금액은 `null`이고 명시적 0원과 다릅니다. 만 원은 소수 넷째 자리까지 허용하며 원 미만이나 안전 정수 범위를 넘는 입력은 반올림하지 않고 거부합니다.

공식 조회값과 사용자 추정값은 출처를 구분해 표시하며 조회일·퇴직 가정·세전/세후가 없는 금액은 결과로 표시하지 않습니다. 제도 변경 시 값의 소속을 바꾸지 않고 제도별 입력을 유지합니다. 준비 입력을 완료해도 자동 계산 결과는 계산 불가입니다. 근거와 미확인 사항은 `docs/pension-calculation-research.md`를 따릅니다.

퇴직수당 판정 계층은 `civil-retirement-allowance.ts`와 `private-retirement-allowance.ts`로 분리했습니다. `retirement-allowance-validation.ts`는 날짜·인정월수·입력 출처·제외 사유를 검증하고, `retirement-allowance.ts`는 결과 계약을 정의합니다. 날짜는 인수로 받으며 함수 내부에서 오늘 날짜를 결정하거나 입력·공식 조회값을 변경하지 않습니다.

현재 법적 금액 계산은 양 제도 모두 차단되어 있습니다. 지급비율·33년 상한은 출처가 있는 참고 메타데이터이며, 실제 적용 기간·적용 지급률·금액은 모두 null입니다. 년·월 입력을 정수 개월로 정규화하는 것 외에 경력 감축·상한 배분·급여 곱셈·끝수 처리를 실행하지 않습니다. 공식 조회액은 `SchemeInputs.allowance`, 앱 판정용 원장은 `SchemeInputs.preparation`에 분리하고 판정 결과는 파생 값으로 생성합니다.

공식 숫자 사례·부칙·급여 끝수 처리 검증 전에는 사용자 선택이나 입력 완성만으로 활성화할 수 없습니다. 새 테스트는 검증되지 않은 금액이 반환되지 않는지 확인하며, 임의 소득을 법적 정답 사례로 취급하지 않습니다.

공제회 모듈은 `ktcu-input.ts`(초깃값·타입), `ktcu-products.ts`(공식 확인 자료의 상품별 메타데이터), `ktcu-validation.ts`(입력·날짜·가정 범위 검사), `ktcu-simulation.ts`(순수 수학 모델)로 분리합니다. 장기저축 적립 모델은 다른 상품에 사용하지 않습니다. 가상 인출은 모든 공식 상품과 독립된 일반 자금 모델입니다.

공식 상품의 급여 산식·세금·일자별 금리·끝수 검증은 미완료입니다. 자체 모델은 월 수익률을 10^-12 정밀도로 고정한 후 BigInt로 원 단위 이자를 반올림하며, 가상 인출액을 내림하고 마지막 회차 잔액을 정산합니다. 공식 예시의 백만원 단위 규모 비교는 정확한 지급액 검증이 아닙니다. 세후 계산은 하지 않습니다. 상세 근거는 `docs/ktcu-calculation-research.md`를 참조하세요.
